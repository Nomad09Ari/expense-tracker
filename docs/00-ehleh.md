# Долоо хоног 0 — Эхлэх

Энэ хуудсанд шинэ ойлголт байхгүй. Зөвхөн орчноо ажиллуулаад, ажлын урсгалыг нэг удаа
эхнээс нь дуустал туулна. Ойролцоогоор **1.5 цаг**.

> **Аппын бүх текст Япон хэл дээр байна.** Товч, шошго, алдааны мессеж бүгд.
> Харин энэ `docs/` доторх хичээлүүд Монгол — тэдгээр нь аппын хэсэг биш.

Төгсгөлд нь:
- localhost дээр Next.js апп ажиллаж байна
- GitHub дээр repo байна
- Нэг PR нээгээд, нэгтгэж үзсэн байна

---

## 1. Юу суусан байх ёстой вэ

| Юу | Шалгах тушаал | Байх ёстой |
|---|---|---|
| Node.js | `node -v` | v20 буюу түүнээс дээш |
| npm | `npm -v` | v10 буюу түүнээс дээш |
| Git | `git --version` | ямар ч хувилбар |

| GitHub бүртгэл | — | байх |

Node байхгүй бол [nodejs.org](https://nodejs.org)-с **LTS** хувилбарыг ав.

- **REST Client** — 2 дахь долоо хоногоос API шалгахад хэрэгтэй

## 3. Төслөө татаж авах

Repo аль хэдийн үүссэн, доторх Next.js төсөл бэлэн байгаа. Энэ бол **чиний repo** —
Vercel, өгөгдлийн сан гэх мэт үйлчилгээ холбоход хэнээс ч зөвшөөрөл хүсэхгүй.

```bash
git clone https://github.com/<repo-ийн-хаяг>.git
cd expense-tracker
npm install
npm run dev
```

`npm install` нь `package.json` дотор жагсаагдсан бүх сан татаж `node_modules` хавтас
үүсгэнэ. Хэдэн зуун мегабайт болох тул git-д ордоггүй — тиймээс clone хийсний дараа
хүн бүр өөрөө нэг удаа ажиллуулдаг.

Хөтчөөрөө **http://localhost:3000** нээ. Next.js-ийн эхний хуудас гарч ирвэл боллоо.

> **Зөвлөмж:** `npm run dev` ажиллаж байх үед terminal чөлөөлөгдөхгүй. Энэ зөв.
> Сервер ажиллаж байна гэсэн үг. Зогсоохдоо `Ctrl+C`. Өөр тушаал бичих бол
> **шинэ terminal нээ** (VS Code дээр `Ctrl+Shift+5`).

## 4. Хавтас юу гэсэн үг вэ

Одоо бүгдийг нь ойлгох шаардлагагүй — гэхдээ нэг удаа хараад ав:

```
expense-tracker/
  app/                 <- Аппын бүх хуудас, бүх backend энд байна
    layout.js          <- Бүх хуудсыг ороосон гадна бүрхүүл (толгой, footer …)
    page.js            <- "/" хаягийн хуудас. Эхлээд үүнийг л засна
    globals.css        <- Ерөнхий CSS, Tailwind-ийн эхлэл
  public/              <- Зураг, icon зэрэг статик файл
  docs/                <- Долоо хоног бүрийн хичээл. Кодтой холбоогүй
  .github/             <- PR-ийн загвар
  package.json         <- Ямар сан ашиглаж байгаа, ямар тушаалууд байгаа
  next.config.mjs      <- Next.js-ийн тохиргоо. Одоохондоо хөндөхгүй
  AGENTS.md            <- Claude-д зориулсан тэмдэглэл (доор тайлбартай)
  .gitignore           <- Git-д битгий оруул гэсэн файлуудын жагсаалт
  node_modules/        <- Татсан сангууд. Хэзээ ч гараар хөндөхгүй
```

> **`AGENTS.md` гэж юу вэ?** Next.js өөрөө үүсгэдэг файл. Дотор нь "энэ бол чиний
> мэддэг Next.js биш, шинэ хувилбар — код бичихээсээ өмнө баримт бичгийг нь уншаарай"
> гэсэн сануулга байдаг. Claude энэ төсөл дээр ажиллахдаа үүнийг автоматаар уншина.
>
> Яагаад хэрэгтэй вэ: Next.js хурдан өөрчлөгддөг. Claude хуучин хувилбарын дадлаар
> код бичих эрсдэлтэй. Энэ файл түүнд "шалгаад бич" гэж хэлж байгаа хэрэг. Битгий
> устгаарай — `next dev` ажиллах бүрт өөрөө эргүүлж бичдэг.

> **Энэ бүтцийг хэн үүсгэсэн бэ?** `npx create-next-app@latest` гэсэн нэг тушаал.
> Хүсвэл өөр хавтсанд нэг удаа ажиллуулж, юу үүсгэдгийг хараад устгаж болно —
> ямар асуулт асуудаг, ямар файл гаргадгийг мэдэж авахад тустай:
> ```bash
> cd C:\dev
> npx create-next-app@latest test-app
> ```
> Үзсэнийхээ дараа `test-app` хавтсаа устгаарай. Бидний төсөлд хэрэггүй.

Хамгийн чухал дүрэм: **`app/` доторх `page.js` нэртэй файл бүр нэг хуудас болно.**

```
app/page.js            ->  localhost:3000/
app/login/page.js      ->  localhost:3000/login
app/settings/page.js   ->  localhost:3000/settings
```

Хавтас үүсгэхэд л шинэ хуудас гарч ирнэ. Router тохируулах, замыг бүртгэх шаардлагагүй.

## 5. Ажиллаж байгааг батлах

`app/page.js`-г нээгээд доторх бүх зүйлийг устгаад ийм болго:

```jsx
export default function Home() {
  return (
    <main className="p-8">
      <h1 className="text-3xl font-bold">支出管理</h1>
      <p className="mt-2 text-gray-600">このアプリは動いています。</p>
    </main>
  );
}
```

Хадгалаад хөтчөө хар. **Refresh хийхгүйгээр** өөрчлөлт орсон байх ёстой. Үүнийг
*hot reload* гэдэг — Next.js файл өөрчлөгдөхийг ажиглаад дэлгэцийг чинь өөрөө шинэчилдэг.

Хэрэв өөрчлөлт ороогүй бол `npm run dev` ажиллаж байгаа эсэхээ шалга.

## 6. `main` руу шууд push хийхгүй

Repo дээр нэг дүрэм тавигдсан байгаа: **`main` салбар хамгаалагдсан.** Тэр руу шууд
push хийх гэвэл git татгалзана.

Оронд нь ажил бүрийг шинэ салбар дээр хийж, PR-аар нэгтгэнэ.

Эхлээд илүү алхам мэт санагдаж магадгүй. Гэхдээ хоёр зүйл өгдөг: өөрчлөлт бүрийг
нэгтгэхээсээ өмнө нэг дор тайван хардаг, мөн ямар нэг зүйл эвдэрвэл яг аль PR-аас
болсныг олоход хормын зуур болно.

Салбарын нэрийг ингэж өгнө:

```
week1/ui          week2/api          week3/wiring          week4/auth
```

Дараагийн хэсэгт бүтэн мөчлөгийг нэг удаа туулна.

## 7. Vercel-тэй холбох

Vercel бол Next.js-ийг үүсгэсэн компанийн hosting. Next.js апп тавихад хамгийн хялбар нь.

1. [vercel.com](https://vercel.com) → **GitHub-аараа нэвтэр**
2. **Add New → Project** → жагсаалтаас `expense-tracker` repo-г сонго
3. Тохиргоог хөндөхгүй → **Deploy**

> **Repo жагсаалтад харагдахгүй бол:** импортын хуудсан дээр
> **"Adjust GitHub App Permissions"** гэсэн холбоос байна. Дараад энэ repo-д зөвшөөрөл
> өгнө. Чи repo-гийн эзэн учраас өөрөө хийж чадна.
>
> Vercel нь GitHub-тай **GitHub App**-аар холбогддог бөгөөд тэр app нь repo эзэмшигчийн
> бүртгэл дээр суудаг. Хэн нэгний repo дээр зүгээр хамтран ажиллагч байвал энэ алхмыг
> хийж чадахгүй — эзэмшигч нь л хийнэ.

Хэдэн минутын дараа `expense-tracker-xxxx.vercel.app` гэсэн линк өгнө. Аппаа интернэтээс
нээж үзээрэй.

### Хэрэв GitHub-тай холбогдох нь болохгүй бол

Vercel-д хоёр дахь зам бий — **терминалаас шууд байршуулах**:

```bash
npx vercel
```

Эхний удаад браузераар нэвтрэхийг хүснэ, дараа нь хэдэн асуулт асуугаад л байршуулна.
GitHub огт оролцохгүй, локал хавтаснаас чинь шууд явна.

Ялгаа нь:

| | GitHub холболт | `npx vercel` |
|---|---|---|
| `main` руу merge хийхэд | автоматаар шинэчлэгдэнэ | гараар дахин ажиллуулна |
| PR бүрийн preview линк | ✅ | ❌ |
| Тохируулах | Нэг удаа | Байршуулах бүрт тушаал |

Аль нь ч ажиллана. GitHub холболт нь дараа нь илүү тохь тухтай, гэхдээ **энэ алхам дээр
гацаж суух хэрэггүй** — эхлээд `npx vercel`-ээр гаргаад, дараа нь тайван үедээ GitHub-аа
холбож болно.

Одооноос эхлээд:
- `main` руу нэгтгэх бүрт **автоматаар шинэчлэгдэнэ**
- PR нээх бүрт тухайн PR-ийн **тусдаа урьдчилсан линк** үүснэ

Тэр урьдчилсан линк нь дизайны өөрчлөлтөө хуваалцахад маш тохиромжтой — код уншихгүйгээр
шууд нүдээр харна.

> **Энэ бол 1 дэх долоо хоногийн урьдчилсан нөхцөл биш.** Vercel дээр ямар нэг зүйл
> гацвал орхиод үргэлжлүүл — [Долоо хоног 1](week-1.md)-ийн даалгавар 1.1, 1.2 хоёр
> локал дээр бүрэн ажиллана. Deploy-г 1.3 хүртэл хойшлуулж болно.

## 8. Ажлын урсгалыг нэг удаа туулах

5 дугаарт `app/page.js`-г өөрчилсөн. Тэр өөрчлөлт одоо хадгалагдаагүй байгаа. Түүнийг
ашиглаад бүтэн мөчлөгийг нэг удаа туулъя.

```bash
# 1. Шинэ салбар үүсгэ. Хадгалаагүй өөрчлөлт чинь хамт нүүнэ
git switch -c chore/hello

# 2. Юу өөрчлөгдснийг хар
git status
git diff

# 3. Хадгал
git add .
git commit -m "chore: replace starter page"

# 4. GitHub руу түлх
git push -u origin chore/hello
```

GitHub руу орвол **"Compare & pull request"** гэсэн шар товч гарч ирнэ. Дар.

PR-ийн тайлбарт загвар бэлэн байна. Бөглөөд **Create pull request**.

Хэсэг хүлээвэл Vercel PR дотор preview линк үлдээнэ. Нээж үз — энэ бол **зөвхөн энэ
салбарын** хувилбар, `main` хэвээрээ. Дараа нь **Merge pull request** дараад нэгтгэ.

Эцэст нь локал дээрээ:

```bash
git switch main
git pull
git branch -d chore/hello
```

Сүүлийн гурван тушаал чухал. `git pull` хийхгүй бол локал `main` чинь GitHub дээрхээсээ
хоцорч, дараагийн салбарыг хуучин кодоос эхлүүлнэ.

Энэ мөчлөгийг сарын турш олон удаа давтана. Одоо цээжлэх шаардлагагүй — хэрэглэх тусмаа
өөрөө суух болно.

> **Хэрэв `main` дээр байхдаа санамсаргүй өөрчилчихвөл:** сандрах хэрэггүй, өөрчлөлт
> тань алга болохгүй. `git switch -c <шинэ-салбар>` гэж бичихэд бүх хадгалаагүй
> өөрчлөлт шинэ салбар руугаа хамт нүүнэ. Дээрх 1 дүгээр алхам яг үүнийг хийж байна.

## Commit бичих товч дүрэм

Эхэнд нь ямар төрлийн өөрчлөлт болохыг тавина:

```
feat: add expense form          # шинэ функц

Яагаад хэрэгтэй вэ: 3 сарын дараа `git log` хараад юу болсныг хэдхэн секундэд ойлгоно.

## Гацвал

| Шинж тэмдэг | Юу хийх |
|---|---|
| `npm run dev` ажиллахгүй | `npm install` дахин ажиллуул |
| `Turbopack is not supported on this platform` эсвэл `An Application Control policy has blocked this file` | Windows-ийн хамгаалалт Next.js-ийн хурдасгуур файлыг блоклосон байна. `npm run dev -- --webpack` гэж ажиллуул. Арай удаан ч бүрэн ажиллана. Байнга хэрэглэх бол `package.json`-ы `"dev"` мөрийг `"next dev --webpack"` болго |
| Порт 3000 завгүй гэнэ | Өмнөх серверээ `Ctrl+C`-ээр зогсоо, эсвэл `npm run dev -- -p 3001` |
| Хуудас цагаан хоосон | Хөтчийн DevTools → **Console** таб нээ. Улаан алдаа байна |
| Tailwind класс ажиллахгүй | Файлаа хадгалсан уу? `className` бичсэн үү (`class` биш) |
| Git "rejected" гэнэ | `git pull` хийгээд дахин түлх |
