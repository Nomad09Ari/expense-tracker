# Долоо хоног 3 — Хоёрыг холбох

Энэ бол бүхэл төслийн гол долоо хоног. Өмнөх хоёр долоо хоногт хоёр тусдаа программ
барьсан. Одоо тэднийг ярилцуулна.

Долоо хоногийн эцэст чиний толгойд бүтэн зам тодрох ёстой:

```
Товч дарав → fetch → API route → JSON файл → буцав → state шинэчлэгдэв → дэлгэц өөрчлөгдөв
```

---

## Энэ долоо хоногт бид юуг барих вэ

`app/page.js` доторх хуурамч датаг устгаад, серверээс ирдэг болгоно.

Сонсоход энгийн. Гэхдээ шинэ асуудал дагуулж ирнэ: **дата тэр даруй ирдэггүй.**

Хуурамч дата санах ойд байсан — 0 миллисекунд. Серверийн дата сүлжээгээр явна —
10 миллисекунд ч байж болно, 3 секунд ч байж болно, огт ирэхгүй ч байж болно.

Энэ долоо хоногийн жинхэнэ сэдэв бол `fetch` биш. **Хугацаа ба алдаа** юм.

> Prompt бичих зарчим: [Claude-тай хамт код бичих](claude-ashiglah.md)

---

## Ойлголт 1 — Гурван төлөв

### Асуудал юу вэ

Ихэнх шинэ хөгжүүлэгч кодоо ингэж бичдэг:

```jsx
const [expenses, setExpenses] = useState([]);
// ... серверээс татна ...
return <ExpenseList expenses={expenses} />;
```

Дата ирэхээс өмнө `expenses` нь `[]` байна. Тэгэхээр хэрэглэгч эхний хагас секундэд
**"Одоохондоо зардал алга"** гэсэн бичиг харна. Дараа нь гэнэт 12 зардал гарч ирнэ.

Энэ бол алдаа. Хоосон биш байсан — зүгээр л **хараахан ирээгүй** байсан.

### Хэрхэн шийддэг вэ

Серверээс ирдэг дата бүр гурван төлөвийн аль нэгэнд байдаг:

| Төлөв | Утга | Дэлгэц дээр |
|---|---|---|
| **Ачаалж байна** | Хүсэлт явсан, хариу хүлээж байна | Skeleton, spinner, "Уншиж байна…" |
| **Алдаа** | Хариу ирсэн ч бүтэлгүйтсэн, эсвэл огт ирээгүй | Алдааны мессеж + "Дахин оролдох" товч |
| **Амжилттай** | Дата ирлээ | Дата (эсвэл жинхэнэ хоосон төлөв) |

Гурвуулаа UI-д илэрхийлэгдэх ёстой:

```jsx
const [books, setBooks] = useState([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);

if (loading) return <p>Уншиж байна…</p>;
if (error) return <p className="text-red-600">{error}</p>;
if (books.length === 0) return <p>Ном алга байна</p>;
return <BookList books={books} />;
```

Дарааллыг анзаараарай: **loading → error → хоосон → дата.** Энэ дараалал чухал. Ачаалж
байхад "хоосон" гэж хэлж болохгүй, алдаа гарсан үед хоосон жагсаалт үзүүлж болохгүй.

### Түгээмэл буруу ойлголт

**"Локал дээр хурдан ажиллаж байгаа болохоор loading төлөв хэрэггүй."**

Чиний сервер чиний компьютер дээр байгаа тул 2 миллисекунд болж байна. Жинхэнэ
хэрэглэгч гар утсаараа, дүүрсэн сүлжээгээр, өөр тивд байгаа сервер рүү хандана. Тэнд
2 секунд болно.

Үүнийг өөрөө туршиж үзэх арга бий — доор `Slow 3G` дасгал байна.

## Ойлголт 2 — useEffect

### Асуудал юу вэ

Компонент дотор шууд `fetch` бичвэл юу болох вэ?

```jsx
function Page() {
  const [books, setBooks] = useState([]);
  fetch("/api/books").then(...)   // ❌
  return <div>...</div>;
}
```

Хүсэлт амжилттай болно → `setBooks` дуудагдана → компонент дахин ажиллана → `fetch`
дахин дуудагдана → `setBooks` → дахин ажиллана… **төгсгөлгүй давталт.**

### Хэрхэн шийддэг вэ

`useEffect` нь "энэ кодыг дэлгэц зурагдсаны дараа ажиллуул, гэхдээ **зөвхөн тодорхой
нөхцөлд**" гэж хэлэх арга.

```jsx
"use client";
import { useState, useEffect } from "react";

export default function Books() {
  const [books, setBooks] = useState([]);

  useEffect(() => {
    fetch("/api/books")
      .then((res) => res.json())
      .then((data) => setBooks(data));
  }, []);   // <- энэ хоосон массив хамгийн чухал хэсэг

  return <BookList books={books} />;
}
```

### Хоёр дахь аргумент — dependency array

Тэр `[]` нь "хэзээ дахин ажиллах вэ" гэдгийг хэлж байна:

```jsx
useEffect(() => { ... }, []);           // Зөвхөн НЭГ удаа, эхэнд
useEffect(() => { ... }, [category]);   // category өөрчлөгдөх бүрт
useEffect(() => { ... });               // ❌ АЖИЛЛАХ БҮРТ — бараг үргэлж алдаа
```

Гурав дахь хувилбар нь дээрх төгсгөлгүй давталтыг үүсгэнэ. Хэрэв Claude чамд
dependency array-гүй `useEffect` буцаавал зогсоод асуу.

### Түгээмэл буруу ойлголт

**"`useEffect` дотор `async` шууд бичиж болно."**

Болохгүй:

```jsx
useEffect(async () => { ... }, []);   // ❌
```

Дотор нь функц үүсгэж дууд:

```jsx
useEffect(() => {
  async function load() {
    const res = await fetch("/api/books");
    const data = await res.json();
    setBooks(data);
  }
  load();
}, []);
```

### Хөгжүүлэлтийн үед хоёр удаа ажиллах

Next.js хөгжүүлэлтийн горимд `useEffect`-ийг **зориуд хоёр удаа** ажиллуулдаг (React
Strict Mode). Network таб дээр ижил хүсэлт хоёр гарч ирвэл гайхах хэрэггүй — энэ нь
кодны алдаа биш. Production дээр нэг л удаа ажиллана.

Яагаад ингэдэг вэ: цэвэрлэгээ шаардлагатай эффектийн алдааг эрт илрүүлэхийн тулд.
Одоохондоо мэдэж байхад хангалттай.

## Ойлголт 3 — fetch

### Үндсэн хэлбэр

```js
const res = await fetch("/api/books");        // хариу ирлээ
const data = await res.json();                // body-г JSON болгож задаллаа
```

Хоёр `await` байгаа нь санамсаргүй биш. Эхнийх нь **толгой хэсэг** ирэхийг хүлээж
байна (status code гэх мэт), хоёр дахь нь **body бүхэлдээ** ирж дуусахыг хүлээж байна.

### Хамгийн олон хүн бүдэрдэг зүйл

**`fetch` нь `404`, `500` дээр алдаа шиддэггүй.**

Сүлжээ бүхэлдээ тасарсан үед л шиднэ. Сервер `500` буцаасан бол `fetch`-ийн хувьд
"амжилттай" — хариу ирсэн шүү дээ.

Тиймээс өөрөө шалгах ёстой:

```js
const res = await fetch("/api/books");

if (!res.ok) {
  throw new Error("Ном татаж чадсангүй");
}

const data = await res.json();
```

`res.ok` нь status `200-299` бол `true`, бусад тохиолдолд `false`.

Үүнийг мартвал юу болох вэ: сервер `{ error: "..." }` буцаана, чи түүнийг массив гэж
бодоод `.map()` дуудна, `data.map is not a function` гэсэн ойлгомжгүй алдаа гарна.
Жинхэнэ асуудал огт өөр газар байсан.

### `try` / `catch` / `finally`

```js
async function load() {
  setLoading(true);
  setError(null);
  try {
    const res = await fetch("/api/books");
    if (!res.ok) throw new Error("Татаж чадсангүй");
    setBooks(await res.json());
  } catch (e) {
    setError(e.message);
  } finally {
    setLoading(false);
  }
}
```

`finally` нь амжилттай болсон ч, алдаа гарсан ч ажиллана. `setLoading(false)`-г яг
энд бичих нь чухал — `catch` дотор бичихээ мартвал алдааны үед spinner мөнхөд эргэнэ.

## Ойлголт 4 — Дата өөрчилсний дараа юу хийх вэ

Шинэ зардал POST-оор илгээлээ. Сервер хадгаллаа. Одоо дэлгэц дээр яаж гарах вэ?

Хоёр арга бий:

**① Дахин татах (refetch)** — POST амжилттай болмогц `GET`-ээ дахин дуудна.

```js
await createExpense(newOne);
await loadExpenses();      // жагсаалтаа шинэчилнэ
```

Давуу тал: дэлгэц дээрх зүйл серверийнхтэй **үргэлж таарна**. Хэрэв сервер `id`,
огноо зэргийг өөрөө үүсгэдэг бол чиний таамаг биш, жинхэнэ утга харагдана.
Сул тал: нэг нэмэлт хүсэлт.

**② Гараар нэмэх** — серверийн хариуг шууд state-даа нэмнэ.

```js
const created = await createExpense(newOne);
setExpenses([...expenses, created]);
```

Хурдан, гэхдээ зөрөх магадлалтай.

**Энэ төсөлд ① сонгоно.** Учир нь одоо чухал зүйл нь хурд биш, **дэлгэц дээрх зүйл
серверт байгаатай таарч байх** явдал. Апп томрох тусмаа энэ асуудал хүндэрдэг —
одооноос зөв дадал тогтоох нь дээр.

## Ойлголт 5 — Яагаад `lib/api.js` хэрэгтэй вэ

Эхлээд компонент дотроо шууд `fetch` бичнэ. Асуудал нь: удахгүй 5-6 газар `fetch`
бичигдэнэ. Тэгээд:

- URL өөрчлөгдвөл 6 газар засна
- `res.ok` шалгалтыг 6 газар давтана (нэгд нь мартана)
- Компонент чинь харагдац болон сүлжээ хоёрын аль алиныг хариуцна

Шийдэл нь бүх хүсэлтийг нэг файлд цуглуулах:

```js
// lib/api.js
async function request(url, options) {
  const res = await fetch(url, options);
  if (!res.ok) {
    const body = await res.json().catch(() => ({}));
    throw new Error(body.error || "Хүсэлт амжилтгүй боллоо");
  }
  if (res.status === 204) return null;
  return res.json();
}

export function getBooks() {
  return request("/api/books");
}

export function createBook(book) {
  return request("/api/books", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(book),
  });
}
```

Одоо компонент чинь ингэж болно:

```js
const books = await getBooks();
```

Компонент нь HTTP, JSON, status code гэж юу байдгийг мэдэхээ больлоо. Зөвхөн
"ном авчир" гэж хэлж байна.

Энэ бол 2 дахь долоо хоногт `lib/db.js` хийсэнтэй **яг ижил санаа**, зөвхөн нөгөө талд нь:

```
Компонент  →  lib/api.js  →  HTTP  →  route.js  →  lib/db.js  →  файл
   (юу харуулах)  (яаж асуух)        (юу зөвшөөрөх)  (яаж хадгалах)
```

Давхарга бүр нэг л зүйл мэднэ. Аль нэгийг нь солиход бусад нь хөндөгдөхгүй.

## Даалгавар 3.1 — Серверээс унших

**Зорилго:** хуурамч датаг устгаж, серверээс татах. Гурван төлөвийг зөв харуулах.

**Тулгуурлах ойлголт:** Ойлголт 1, 2, 3

**Алхмууд**

1. `app/page.js`-с `data/sample.js`-ийн импортыг устга.
2. `useState([])` + `loading` + `error` гурван state.
3. `useEffect` дотор `/api/expenses`-с татна.
4. Гурван төлөвийг UI-д харуул.

**Claude-д өгөх prompt-ын жишээ**

```
Next.js App Router, JavaScript, Tailwind.

app/page.js дээр зардлууд одоо data/sample.js-с ирж байгаа. Үүнийг /api/expenses
API-гаас татдаг болгож өөрчилнө.

- useEffect дотор нэг л удаа татна
- loading, error гэсэн хоёр state нэм
- Ачаалж байхад "Уншиж байна…" гарна
- Алдаа гарвал улаан мессеж + "Дахин оролдох" товч гарна
- Дата ирсэн ч хоосон бол одоо байгаа хоосон төлөв гарна

Хязгаарлалт:
- res.ok-г заавал шалга. fetch нь 500 дээр алдаа шиддэггүй.
- useEffect-ийн dependency array хоосон [] байна.
- useEffect-д async функцийг шууд бүү дамжуул, дотор нь функц үүсгэ.
- Шинэ сан бүү нэм (react-query, swr хэрэггүй).

Одоогийн app/page.js:
<кодоо энд тавь>
```

> Сүүлийн хязгаарлалтыг анзаараарай. `react-query` бол сайн сан, гэхдээ одоо түүнийг
> нэмбэл `fetch`, `loading`, `error` гурвыг нь нуучихна — яг сурах гэж байгаа зүйлийг.
> Дараа сурч болно.

**Гарсан кодыг шалгах**

- [ ] `useEffect`-ийн хоёр дахь аргумент `[]` байна (байхгүй **биш**)
- [ ] `if (!res.ok)` шалгалт байна
- [ ] `finally` дотор `setLoading(false)` байна
- [ ] `useEffect(async () => ...)` гэсэн бичиглэл **байхгүй**
- [ ] `data/sample.js`-ийн импорт устсан
- [ ] Ачаалж байхад "хоосон" мессеж **гарахгүй**
- [ ] `react-query`, `swr` гэх мэт шинэ сан нэмээгүй

**Дууссан гэж үзэх шалгуур**

- [ ] Хуудас ачаалахад серверийн дата гарч ирнэ
- [ ] DevTools → Network таб дээр `/api/expenses` хүсэлт харагдана
- [ ] `data/expenses.json`-г гараар засаад refresh хийхэд өөрчлөлт харагдана

### 🔍 Дасгал А — Network таб

DevTools нээ (F12) → **Network** таб → хуудсаа refresh хий.

`expenses` гэсэн мөр дээр дар. Баруун талд:

- **Headers** — ямар method, ямар URL, ямар status code
- **Response** — серверийн буцаасан яг тэр JSON
- **Timing** — хэдэн миллисекунд болсон

**Энэ бол чиний хамгийн чухал багаж.** Ямар нэг зүйл ажиллахгүй байвал эхлээд энд ор.
Ихэнх асуудал энд шууд харагддаг: хүсэлт огт яваагүй, буруу URL руу явсан, `400`
буцаасан, эсвэл ирсэн дата чиний хүлээж байсан хэлбэртэй байгаагүй.

### 🔍 Дасгал Б — Удаашруулаад үз

Network таб дээр дээд талд **"No throttling"** гэсэн жагсаалт байна. **Slow 3G** сонго.

Refresh хий.

Одоо `loading` төлөв чинь хэдэн секунд харагдана. Хэрэв энэ хугацаанд дэлгэц цоо
хоосон эсвэл "зардал алга" гэж бичээд байвал → яг тэр л асуудлыг Ойлголт 1-д ярьсан.

Засаад дахин үз. Сайхан харагдтал нь тохируул. Дараа нь throttling-оо буцааж
**No throttling** болго.

Энэ бол дизайнерын нүд хэрэгтэй болох мөч: **хүлээх хугацаа ч бас дизайн юм.**

### 🔍 Дасгал В — Алдааг харах

`app/api/expenses/route.js`-ийн `GET` функцийн эхэнд түр зуур ийм мөр нэм:

```js
return Response.json({ error: "Түр зуурын алдаа" }, { status: 500 });
```

Refresh хий. Алдааны мессеж чинь гарч ирэх ёстой — цагаан хуудас, эвдэрсэн дэлгэц
эсвэл мөнхөд эргэх spinner **биш**.

Гарахгүй байвал `res.ok` шалгалт чинь дутуу байна.

"Дахин оролдох" товч дараад үз (одоохондоо ажиллахгүй — сервер алдаа хэвээрээ).
Дараа нь тэр мөрөө **устгаад** хэвийн болгоорой.

## Даалгавар 3.2 — Серверт бичих

**Зорилго:** нэмэх, устгах хоёрыг серверээр дамжуулах.

**Тулгуурлах ойлголт:** Ойлголт 4

**Алхмууд**

1. Форм илгээхэд `POST /api/expenses` явна.
2. Устгах товч дархад `DELETE /api/expenses/<id>` явна.
3. Хоёулангийн дараа жагсаалтаа дахин татна.
4. Хүсэлт явж байх үед товч `disabled` болно.
5. Хүсэлт бүтэлгүйтвэл мессеж гарна.

**Claude-д өгөх prompt-ын жишээ**

```
Next.js App Router, JavaScript, Tailwind.

app/page.js дээр нэмэх, устгах хоёрыг серверээр дамжуулна.

- Форм илгээхэд POST /api/expenses руу JSON илгээнэ
- Устгах товч дархад DELETE /api/expenses/<id> руу илгээнэ
- Аль аль нь амжилттай болсны дараа жагсаалтаа дахин татна
- Хүсэлт явж байх үед тухайн товч disabled болж, "Хадгалж байна…" гэж харагдана
- Хүсэлт бүтэлгүйтвэл алдааны мессеж харагдана, жагсаалт хэвээрээ үлдэнэ

Хязгаарлалт:
- POST-д Content-Type: application/json header заавал байна
- res.ok-г заавал шалга
- Жагсаалтаа шинэчлэхдээ дахин татах аргыг ашигла
- Шинэ сан бүү нэм

Одоогийн app/page.js:
<кодоо энд тавь>
```

**Гарсан кодыг шалгах**

- [ ] POST-д `headers: { "Content-Type": "application/json" }` байна
- [ ] `body: JSON.stringify(...)` — объектыг шууд дамжуулаагүй
- [ ] Хүсэлтийн дараа жагсаалт дахин татагдаж байна
- [ ] Хүсэлт явж байх үед товч `disabled` болж байна
- [ ] Бүх `fetch` дээр `res.ok` шалгалт байна
- [ ] Алдаа гарахад жагсаалт цэвэрлэгдээгүй, хэвээрээ үлдэж байна

**Дууссан гэж үзэх шалгуур**

- [ ] Зардал нэмээд **refresh хийхэд хэвээрээ байна** ← энэ бол 1 дэх долоо хоногийн
      асуултын хариу
- [ ] `data/expenses.json` файлд шинэ мөр орсон
- [ ] Устгаад refresh хийхэд устсан хэвээрээ
- [ ] Network таб дээр POST → 201, DELETE → 204 харагдана
- [ ] Хоосон форм илгээхэд `400` ирж, эвтэйхэн мессеж гарна (апп унахгүй)
- [ ] Товч хоёр удаа дарахад хоёр зардал үүсэхгүй (disabled ажиллаж байна)

**Түгээмэл алдаа**

- `Content-Type` header мартах → сервер body-г уншиж чадахгүй, ойлгомжгүй алдаа гарна.
- `JSON.stringify` мартаж объектыг шууд дамжуулах → сервер рүү `[object Object]`
  гэсэн текст очно.
- Хүсэлт **явахаас өмнө** state-ээ шинэчлэх → сервер алдаа буцаавал дэлгэц дээр
  байхгүй зардал үлдэнэ.
