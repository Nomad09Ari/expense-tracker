# Долоо хоног 2 — Backend гарч ирлээ

## Өнгөрсөн долоо хоногийн асуулт

Зардал нэмээд refresh хийхэд бүгд алга болсон. Учир нь:

Чиний бүх дата `useState` дотор байсан. `useState` нь **хөтчийн санах ойд** амьдардаг.
Хуудас дахин ачаалагдахад тэр санах ой цоо шинээр эхэлдэг — хуучин юу байсныг хэн ч
санахгүй.

Vercel линкээ найздаа илгээвэл тэр цоо хоосон апп харна. Түүний хөтчийн санах ой чинийхтэй
огт өөр. Хоёр өөр компьютер, хоёр өөр санах ой.

Тэгэхээр дата **өөр газар** амьдрах ёстой. Хөтөч бүрд өөрийн гэсэн хувилбар байхгүй,
бүгдийн хувьд нэг л газар. Тэр газар бол **сервер**.

---

## Энэ долоо хоногт бид юуг барих вэ

Аппын нөгөө талыг. Дата серверт хадгалагдана, тэндээсээ ирнэ.

Гол зүйл: энэ долоо хоногт **frontend-ээ огт хөндөхгүй**. Backend-ээ тусад нь барьж,
тусад нь шалгана. Хоёрыг холбох нь 3 дахь долоо хоногийн ажил.

Ингэж салгаж байгаа нь санамсаргүй биш. Backend бол frontend-ийн нэг хэсэг биш —
**өөрөө бие даасан программ**. Түүнийг хөтөчгүйгээр ажиллуулж шалгаж чадаж байж жинхэнэ
ойлгоно.

## Ойлголт 1 — Хоёр программ, нэг апп

### Хэн хаана ажилладаг вэ

```
   ХӨТӨЧ (хэрэглэгчийн компьютер)        СЕРВЕР (үүл дэх компьютер)
   ─────────────────────────────         ──────────────────────────
   React компонентууд                    API route-ууд
   useState                              Дата унших / бичих
   Товч, форм, харагдац                  Хэн юу хийж болохыг шийдэх
                                         Дата
        │                                        │
        └────────────  HTTP  ────────────────────┘
              "Надад зардлуудаа өгөөч"
              "За, энэ байна: [...]"
```

**Хөтөч** хэрэглэгч бүрт өөр. Тэдний харж байгаа зүйл, дарж байгаа товч.
**Сервер** ганцхан. Бүх хэрэглэгч ижил серверт хандана, дата тэнд байна.

Хоёулаа JavaScript бичигдсэн, ижил төсөл дотор байгаа ч **өөр өөр компьютер дээр
ажиллаж байгаа** гэдгийг мартаж болохгүй. Тэд хоорондоо шууд функц дуудаж чадахгүй.
Зөвхөн **мессеж илгээж** харилцана. Тэр мессежийн дүрмийг HTTP гэдэг.

### Түгээмэл буруу ойлголт

**"Ижил төсөл дотор байгаа юм чинь `lib/db.js`-ийг компонентоосоо шууд дуудчихаж
болохгүй юу?"**

Next.js-д техникийн хувьд болно. Гэхдээ энэ төслийн турш **зориуд тэгэхгүй.** Учир нь:

1. Хил тодорхой байвал юу хаана болж байгааг харна. Дараа нь бүдгэрүүлж болно, гэхдээ
   эхлээд тодорхой харах хэрэгтэй.
2. Ирээдүйд гар утасны апп эсвэл өөр вэбсайт ижил датад хандахыг хүсвэл, тэр нь React
   компонент дуудаж чадахгүй. **HTTP-ээр л хандана.** API байгаа цагт хэн ч хандаж чадна.

## Ойлголт 2 — HTTP гэж юу вэ

HTTP бол хөтөч сервер хоёрын ярианы дүрэм. Хүсэлт бүр 4 хэсэгтэй:

| Хэсэг | Юу гэсэн үг | Жишээ |
|---|---|---|
| **Method** | Ямар төрлийн үйлдэл | `GET`, `POST`, `PATCH`, `DELETE` |
| **URL** | Юун дээр | `/api/expenses`, `/api/expenses/abc123` |
| **Body** | Ямар дата (заавал биш) | `{ "amount": 12000 }` |
| **Status code** | Үр дүн (хариунд) | `200`, `201`, `404`, `500` |

### Method-ууд

| Method | Утга | Жишээ |
|---|---|---|
| `GET` | Надад өгөөч. Юу ч бүү өөрчил | Зардлуудыг унших |
| `POST` | Шинийг үүсгэ | Шинэ зардал нэмэх |
| `PATCH` | Байгааг нь өөрчил | Дүнг нь засах |
| `DELETE` | Устга | Зардал устгах |

Эдгээр бол зөвхөн тохиролцоо. `GET`-ээр дата устгаж бичих техникийн боломжтой — гэхдээ
бүх хүн, бүх багаж (хөтөч, кэш, гар утасны апп) эдгээр утгыг тооцоолж ажилладаг.
Тохиролцоог зөрчвөл гэнэтийн зүйл болно.

### Status code

Хариултын эхний цифр л ихэнхийг хэлнэ:

| Код | Утга | Хэзээ |
|---|---|---|
| `200` | За, боллоо | GET, PATCH, DELETE амжилттай |
| `201` | Шинээр үүслээ | POST амжилттай |
| `400` | Чиний илгээсэн дата буруу | Дүн нь тоо биш байна |
| `401` | Чи хэн бэ? Нэвтрээгүй байна | (4 дэх долоо хоногт) |
| `403` | Чамайг мэдэж байна, гэхдээ эрх байхгүй | (4 дэх долоо хоногт) |
| `404` | Ийм зүйл олдсонгүй | Байхгүй `id`-г устгах гэсэн |
| `500` | Сервер дээр алдаа гарлаа | Кодонд чинь алдаа байна |

**`4xx` бол хүсэлт илгээгчийн алдаа. `5xx` бол серверийн алдаа.** Энэ ялгааг мэдэх нь
алдаа хайхад асар их цаг хэмнэнэ: `400` ирвэл юу илгээснээ хар, `500` ирвэл серверийн
кодоо хар.

## Ойлголт 3 — Route handler

### Next.js-д backend хаана байдаг вэ

Санаж байгаа бол `app/` доторх `page.js` файл бүр хуудас болдог. Үүнтэй яг ижилхэн
дүрэм: **`route.js` файл бүр API цэг болно.**

```
app/page.js                      ->  localhost:3000/           (хуудас)
app/api/expenses/route.js        ->  localhost:3000/api/expenses      (API)
app/api/expenses/[id]/route.js   ->  localhost:3000/api/expenses/abc  (API)
```

### Жижиг жишээ

Номын API:

```js
// app/api/books/route.js
const books = [
  { id: "b1", title: "こころ", author: "夏目漱石" },
  { id: "b2", title: "羅生門", author: "芥川龍之介" },
];

export async function GET() {
  return Response.json(books);
}

export async function POST(request) {
  const body = await request.json();
  const newBook = { id: crypto.randomUUID(), ...body };
  books.push(newBook);
  return Response.json(newBook, { status: 201 });
}
```

Гурван зүйлийг анзаараарай:

1. **Функцийн нэр нь HTTP method.** `GET`, `POST`, `DELETE` гэж экспортлоно. Next.js
   нэрээр нь таньж, зөв хүсэлтэд зөв функцийг дуудна. Router тохируулах шаардлагагүй.
2. **`Response.json(...)`** нь JavaScript объектыг JSON болгож хариу болгож буцаана.
3. **`await request.json()`** нь ирсэн хүсэлтийн body-г уншина. `await` заавал —
   дата сүлжээгээр ирж байгаа тул шууд бэлэн байдаггүй.

### `[id]` гэсэн хаалт

Хавтасны нэрийг `[id]` гэж хаалтад бичвэл тэр хэсэг нь **хувьсагч** болно.

```js
// app/api/books/[id]/route.js
export async function DELETE(request, { params }) {
  const { id } = await params;
  // ... id-тай номыг устгана
  return new Response(null, { status: 204 });
}
```

`/api/books/b1` руу DELETE илгээвэл `id` нь `"b1"` болно.

## Ойлголт 4 — JSON

JSON бол дата дамжуулах бичиглэл. JavaScript объекттой маш төстэй, гэхдээ хатуу дүрэмтэй:

```json
{
  "id": "b1",
  "title": "こころ",
  "pages": 240,
  "available": true,
  "tags": ["小説", "近代文学"]
}
```

Ялгаа нь:
- Түлхүүр бүр **хашилтанд** байна (`"id"`, `id` биш)
- Зөвхөн давхар хашилт (`"`), дан хашилт (`'`) болохгүй
- Сүүлийн элементийн ард таслал байж болохгүй
- Функц, `undefined`, тайлбар байж болохгүй

**Яагаад JSON вэ?** Учир нь сүлжээгээр зөвхөн текст л дамждаг. JavaScript объектыг
шууд илгээх боломжгүй — эхлээд текст болгоно (`JSON.stringify`), нөгөө талд нь эргүүлж
объект болгоно (`JSON.parse`).

Мөн JSON бол **бүх хэлний ойлгодог** формат. Гар утасны апп нь Swift эсвэл Dart дээр
бичигдсэн байлаа ч чиний API-гаас ирсэн JSON-г ойлгоно. Яг тиймээс дата солилцооны
нийтлэг хэл болсон юм.

## Ойлголт 5 — async / await

### Асуудал юу вэ

Зарим үйлдэл цаг зарцуулдаг: файл унших, өгөгдлийн санд хандах, сүлжээгээр хүсэлт
илгээх. Эдгээр нь миллисекунд эсвэл секунд болдог.

Хэрэв JavaScript тэднийг хүлээж зогсдог байсан бол програм тэр хугацаанд бүхэлдээ
хөлдөх байсан.

### Хэрхэн шийддэг вэ

Ийм үйлдлүүд **шууд үр дүн буцаадаггүй.** "Дараа нь бэлэн болно" гэсэн амлалт
(Promise) буцаадаг. `await` гэдэг нь "энэ амлалт биелтэл нааш хүлээ" гэсэн үг.

```js
import { readFile } from "node:fs/promises";

export async function GET() {
  const text = await readFile("data/books.json", "utf-8");
  const books = JSON.parse(text);
  return Response.json(books);
}
```

`await` ашиглах бол функцээ `async` гэж зарлана. Хоёр нь үргэлж хамт явна.

### Хамгийн түгээмэл алдаа

`await` мартах:

```js
const text = readFile("data/books.json", "utf-8");  // ❌ await байхгүй
console.log(text);  // Promise { <pending> } гэж хэвлэгдэнэ
```

Дата биш, амлалт өөрөө гарч ирнэ. `Promise { <pending> }` эсвэл `[object Promise]`
гэсэн зүйл харагдвал `await` дутуу байна гэсэн үг. Энэ бол хамгийн олон таардаг
алдааны нэг — тэмдгийг нь цээжлээрэй.

## Ойлголт 6 — Яагаад `lib/db.js` тусдаа файл байх ёстой вэ

Файл унших, бичих кодыг route handler дотроо шууд бичиж болно. Гэхдээ тусдаа файлд
гаргах нь илүү.

```
app/api/expenses/route.js     "Хүсэлт ирлээ. Юу хийх ёстой вэ?"
        │
        ↓  getAll(), create(), remove()
lib/db.js                     "Дата хаана, яаж хадгалагдаж байна вэ?"
        │
        ↓
data/expenses.json
```

Дунд нь **давхарга** үүсгэж байна. Route handler нь дата хаана хадгалагдаж байгааг
мэдэхгүй — зөвхөн `getAll()` дуудна.

Энэ нь одоо илүү ажил мэт санагдаж магадгүй. Гэхдээ 4 дэх долоо хоногт `lib/db.js`-ийн
дотор талыг JSON файлаас Postgres руу солино. Тэр үед `app/api/` доторх код **огт
өөрчлөгдөхгүй.** Энэ бол хийсвэр онол биш — өөрөө `git diff`-ээ хараад батлах болно.

### ⚠️ Нэг далд урхи — `writeFile` нь бүтнээр бичдэггүй

Хэдэн удаа зардал нэмсний дараа гэнэт ийм алдаа гарч магадгүй:

```
SyntaxError: Unexpected end of JSON input
    at JSON.parse (<anonymous>)
```

Кодод чинь алдаа байхгүй. Болж байгаа зүйл нь:

`writeFile` файлыг **эхлээд хоосруулж**, дараа нь шинэ агуулгыг бичдэг. Тэр хоёрын
хооронд маш богино агшин байна. Яг тэр агшинд өөр хүсэлт файлыг уншвал **хоосон текст**
авна. `JSON.parse("")` унана.

Хоёр зүйлээр шийднэ.

**① Хоосон файлыг тэвчих**

```js
const text = await readFile(file, "utf-8");
if (!text.trim()) return fallback;   // бичиж байх зуур хоосон байж болно
return JSON.parse(text);
```

**② Түр файлаар дамжуулж бичих**

```js
import { writeFile, rename } from "node:fs/promises";

const tmp = target + ".tmp";
await writeFile(tmp, JSON.stringify(data, null, 2), "utf-8");
await rename(tmp, target);   // rename нь атомт — хагас файл гэж байхгүй
```

Түр файлд бүтнээр нь бичээд, дараа нь нэрийг нь солино. Файлын нэр солих үйлдэл нь
**хуваагдашгүй** — уншиж байгаа тал эсвэл хуучин файлыг бүтнээр, эсвэл шинийг бүтнээр
харна. Дунд төлөв гэж байхгүй.

> **Энэ бол өгөгдлийн сангийн шалтгаануудын нэг.** Файлаар ажиллах бүрт ийм жижиг
> урхинуудыг өөрөө шийдэх хэрэгтэй болно. Өгөгдлийн сан эдгээрийг бүгдийг нь чиний
> өмнөөс хийчихсэн байдаг. 4 дэх долоо хоногт эргэж ярина.

## Даалгавар 2.3 — Устгах, засах, шалгах

**Зорилго:** CRUD-ыг бүрэн болгож, буруу датаг хамгаалах.

**Тулгуурлах ойлголт:** Ойлголт 2 (status code)

3. Байхгүй `id` ирвэл `404` буцаа.
4. POST дээр шалгалт нэм: `amount` нь тоо байх ёстой, эерэг байх ёстой, `category` нь
   зөвшөөрөгдсөн гурвын нэг байх ёстой. Буруу бол `400` буцаа.

**Claude-д өгөх prompt-ын жишээ**

```
Next.js App Router, JavaScript.

1. lib/db.js-д хоёр функц нэм:
   - remove(id) — устгана. Олдоогүй бол false, устгасан бол true буцаана.
   - update(id, changes) — өөрчилнө. Олдоогүй бол null, олдвол шинэчилсэн зардлыг буцаана.

2. app/api/expenses/[id]/route.js үүсгэ:
   - DELETE — олдоогүй бол 404, устгасан бол 204
   - PATCH — олдоогүй бол 404, өөрчилсөн бол 200 + шинэчилсэн зардал

3. app/api/expenses/route.js-ийн POST дээр шалгалт нэм:
   - amount байхгүй, тоо биш, эсвэл 0-с бага бол 400 буцаа
   - category нь food/transport/other-ийн аль нь ч биш бол 400 буцаа
   - エラーの本文は { error: "..." } の形。メッセージは日本語で、何が悪いか具体的に
     (例:「金額は0より大きい数値を入力してください」)

Хязгаарлалт:
- Route handler дотор fs шууд бүү дууд.
- Next.js-ийн шинэ хувилбарт params нь Promise тул await хийх шаардлагатай эсэхийг шалга.
- Шинэ сан бүү нэм (zod гэх мэт хэрэггүй).
```

**Гарсан кодыг шалгах**

- [ ] Байхгүй `id`-д `404` буцааж байна, `500` **биш**
- [ ] Буруу датад `400` буцааж байна
- [ ] Алдааны хариу нь `{ error: "..." }` гэсэн ойлгомжтой **Япон** мессежтэй, хоосон биш
- [ ] `amount`-ыг `Number(...)` болгож хөрвүүлж байна
- [ ] Устгахад `204` эсвэл `200` буцааж байна (аль нь ч болно, гол нь тогтвортой)
- [ ] `[id]` хавтасны нэр яг ийм бичигдсэн, хаалттайгаа

**Дууссан гэж үзэх шалгуур**

`docs/requests.http`-ээр эдгээрийг **нэг бүрчлэн** шалга:

- [ ] `GET /api/expenses` → `200`, жагсаалт
- [ ] `POST` зөв датагаар → `201`
- [ ] `POST` `amount: "гурван мянга"` → `400`
- [ ] `POST` `amount: -500` → `400`
- [ ] `POST` `category: "puppies"` → `400`
- [ ] `DELETE /api/expenses/<бодит id>` → `204`, файлаас алга болсон
- [ ] `DELETE /api/expenses/байхгүй-id` → `404`
- [ ] `PATCH` дүнг өөрчлөх → `200`, файлд өөрчлөгдсөн

**Түгээмэл алдаа**

- Байхгүй `id`-д `500` буцаах. `500` нь "серверийн код эвдэрсэн" гэсэн үг. Хэрэглэгч
  байхгүй зүйл асуусан бол энэ нь **түүний** алдаа — `404`.
- Шалгалтгүйгээр `Number(body.amount)` хийх. `Number("хоол")` нь `NaN` буцаана, `NaN`
  файлд `null` болж бичигдээд дараа нь нийт дүн `NaN` болно.
