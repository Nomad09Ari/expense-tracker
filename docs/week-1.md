# Долоо хоног 1 — Зөвхөн frontend

## Энэ долоо хоногт бид юуг барих вэ

Ажилладаг зардлын бүртгэл. Зардал нэмнэ, жагсаалтад харагдана, устгана, ангиллаар шүүнэ,
нийт дүн бодогдоно. Төгсгөлд нь интернэт дээр гаргана.

Нэг зүйл дутуу байна: **дата хаанаас ирэх вэ?** Энэ долоо хоногт кодондоо бичсэн хуурамч
жагсаалтаас авна. Одоохондоо тэр хангалттай — сервер, өгөгдлийн сан ярихаас өмнө
дэлгэц дээр юу болж байгааг бүрэн ойлгох нь чухал.

Долоо хоногийн төгсгөлд нэг асуудал үлдэнэ. Тэр асуудал 2 дахь долоо хоногийг эхлүүлнэ.

> **Хэрэглэгчид харагдах бүх текст Япон хэл дээр байна.** Товч, шошго, алдааны мессеж,
> ангиллын нэр — бүгд. Доорх жишээ кодууд ч мөн адил. Тайлбар нь Монголоор, код нь
> Япон — энэ хоёрыг ялгаж хараарай.

> Даалгавар бүрт **Claude-д өгөх prompt-ын жишээ** болон **гарсан кодыг шалгах**
> жагсаалт байгаа. Эхлэхийн өмнө [Claude-тай хамт код бичих](claude-ashiglah.md)-ийг
> нэг уншаарай — тэнд ямар зарчмаар бичсэнийг тайлбарласан.

## Ойлголт 1 — Компонент ба props

### Асуудал юу вэ

Нэг хуудсанд 300 мөр JSX бичвэл юу хаана байгааг олохоо болино. Мөн ижил харагдацтай
зүйлийг 20 удаа хуулж бичих болно — нэгийг нь өөрчлөхөд 20-г нь өөрчилнө.

### Хэрхэн шийддэг вэ

Давтагдах хэсгийг **компонент** болгож тусад нь гаргана. Компонент бол зүгээр л JSX
буцаадаг функц. Гаднаас нь өгөх өгөгдлийг **props** гэнэ.

### Жижиг жишээ

Цайны газрын цэс:

```jsx
// MenuItem.js
export default function MenuItem({ name, price }) {
  return (
    <div className="flex justify-between border-b py-2">
      <span>{name}</span>
      <span className="text-gray-500">{price}円</span>
    </div>
  );
}
```

```jsx
// Menu.js
import MenuItem from "./MenuItem";

export default function Menu() {
  return (
    <div>
      <MenuItem name="ミルクティー" price={480} />
      <MenuItem name="ブラックコーヒー" price={380} />
    </div>
  );
}
```

`name`, `price` бол props. `MenuItem` нь тэднийг гаднаас хүлээж авдаг — өөрөө юу гэсэн
цай болохыг мэдэхгүй. Яг тиймээс дахин ашиглагдаж чадаж байна.

### Түгээмэл буруу ойлголт

**Props нэг л чиглэлд урсдаг: эцгээс хүүхэд рүү.** `MenuItem` дотроос `Menu`-гийн датаг
өөрчилж болохгүй. Хүүхэд компонент ямар нэг зүйл өөрчлөх шаардлагатай бол эцэг нь
**функц** props болгож дамжуулна (үүнийг Ойлголт 3-т үзнэ).

## Ойлголт 2 — Жагсаалт харуулах

### Асуудал юу вэ

Цэсэнд 2 цай биш, 40 цай байвал 40 мөр гараар бичих үү? Мөн дата өөрчлөгдвөл яах вэ?

### Хэрхэн шийддэг вэ

JavaScript-ийн `.map()`-аар массивыг JSX-ийн массив болгож хувиргана. React массив
доторх бүх элементийг дэс дараалан гаргана.

### Жижиг жишээ

```jsx
const teas = [
  { id: "t1", name: "ミルクティー", price: 480 },
  { id: "t2", name: "ブラックコーヒー", price: 380 },
  { id: "t3", name: "緑茶", price: 320 },
];

export default function Menu() {
  return (
    <div>
      {teas.map((tea) => (
        <MenuItem key={tea.id} name={tea.name} price={tea.price} />
      ))}
    </div>
  );
}
```

`{}` хаалт нь "энд JavaScript ажиллана" гэсэн үг. Дотор нь массив буцаагаад React түүнийг
дэлгэнэ.

### `key` гэж юу вэ, яагаад хэрэгтэй вэ

React жагсаалт өөрчлөгдөхөд **юу нь өөрчлөгдсөнийг** мэдэх хэрэгтэй. `key` бол мөр
болгоны хувийн дугаар.

`key` байхгүй бол консол дээр анхааруулга гарна. `key={index}` тавьбал анхааруулга
арилна, гэхдээ **асуудал арилахгүй**: жагсаалтын дундаас нэг мөр устгахад дараагийн бүх
мөрний индекс ухарч, React буруу мөрийг шинэчилдэг. Форм эсвэл анимаци байвал энэ нь
харагдахуйц алдаа болно.

**Дүрэм:** `key` нь тухайн зүйлийн өөрийнх нь тогтвортой `id` байх ёстой. Индекс биш.

## Ойлголт 3 — State

### Асуудал юу вэ

Энгийн JavaScript хувьсагч өөрчлөхөд дэлгэц шинэчлэгдэхгүй:

```jsx
let count = 0;

function handleClick() {
  count = count + 1;  // хувьсагч өөрчлөгдлөө, дэлгэц хэвээрээ
}
```

Хөтөч мэдэхгүй байна. Хэн ч түүнд "дахин зурчих" гэж хэлээгүй.

### Хэрхэн шийддэг вэ

React-д **хэлж өгөх** хэрэгтэй. Тэр хэлэх арга нь `useState`.

```jsx
"use client";
import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      押した回数: {count}
    </button>
  );
}
```

`useState(0)` хоёр зүйл буцаана:
- `count` — одоогийн утга
- `setCount` — утгыг өөрчлөх функц

`setCount` дуудагдахад React тухайн компонентыг **дахин ажиллуулж**, шинэ утгаар
дэлгэцийг зурна. Энэ бол React-ийн бүх зүйлийн үндэс.

> **`"use client"` гэж юу вэ?** Next.js-д компонентууд анхдагчаар серверт ажилладаг.
> `useState`, `onClick` зэрэг нь хөтөч дээр л ажиллах ёстой тул файлын хамгийн эхэнд
> `"use client"` гэж бичиж өгнө. Мартвал алдаа гарна — алдааны мессеж нь чамд шууд
> хэлнэ. Бид энэ төслийн турш бүх интерактив хуудсандаа үүнийг бичнэ.

### Массив state-ийг өөрчлөх

Энэ хэсэгт хамгийн олон хүн бүдэрдэг:

```jsx
const [teas, setTeas] = useState([]);

// ❌ Буруу — дэлгэц шинэчлэгдэхгүй
teas.push(newTea);
setTeas(teas);

// ✅ Зөв — ШИНЭ массив үүсгэж өгнө
setTeas([...teas, newTea]);
```

Шалтгаан: React хуучин утга шинэ утга хоёрыг харьцуулж "өөрчлөгдсөн үү?" гэж шалгадаг.
`push` нь яг тэр л массивыг өөрчилдөг тул хуучин, шинэ хоёр нь ижил объект хэвээр —
React ялгааг олж харахгүй.

Устгах бас адилхан — шинэ массив үүсгэнэ:

```jsx
setTeas(teas.filter((tea) => tea.id !== idToRemove));
```

`filter` нь анхны массивыг хөндөхгүй, шинэ массив буцаадаг. Яг тиймээс тохирч байна.

### Түгээмэл буруу ойлголт

**"`setCount` дуудсаны дараа `count` тэр даруй шинэчлэгдэнэ."** Үгүй.

```jsx
setCount(count + 1);
console.log(count);  // хуучин утга хэвлэгдэнэ
```

`count` бол тухайн ажиллагааны хугацаанд тогтмол. Шинэ утга нь **дараагийн** ажиллалтад
гарч ирнэ. Эхлээд эвгүй санагдана, гэхдээ энэ нь React-ийг урьдчилан таамаглахуйц болгодог.

## Ойлголт 4 — Форм (controlled input)

### Асуудал юу вэ

`<input>` нь өөрөө өөрийн доторх текстээ санадаг. Гэтэл React ч бас state-дээ өгөгдлөө
санахыг хүсэж байна. Хоёр газарт хоёр өөр үнэн байвал эрт орой хэзээ нэгэн цагт зөрнө.

### Хэрхэн шийддэг вэ

Input-ыг state-тэй холбоно. Утга нь state-ээс ирнэ, бичих бүрт state шинэчлэгдэнэ.
Ингэснээр **үнэн ганц газар** байна.

```jsx
"use client";
import { useState } from "react";

export default function SearchBox() {
  const [query, setQuery] = useState("");

  return (
    <div>
      <input
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="検索…"
        className="border rounded px-3 py-2"
      />
      <p className="mt-2 text-sm text-gray-500">検索中: {query}</p>
    </div>
  );
}
```

`value={query}` — харагдах зүйл нь state-ээс ирж байна
`onChange` — товчлуур дарагдах бүрт state шинэчлэгдэж байна

### Форм илгээх

```jsx
function handleSubmit(e) {
  e.preventDefault();   // хуудас дахин ачаалагдахаас сэргийлнэ
  // ... энд датаг ашиглана
  setQuery("");         // формоо цэвэрлэнэ
}

return <form onSubmit={handleSubmit}>...</form>;
```

`e.preventDefault()` мартвал хуудас чинь бүхэлдээ дахин ачаалагдаад бүх state алга болно.
Хамгийн олон удаа таардаг алдааны нэг.

## Ойлголт 5 — State-ээс гарган авах утга

### Асуудал юу вэ

Нийт дүн, шүүсэн жагсаалт зэргийг **тусдаа state** болгох уу?

```jsx
const [teas, setTeas] = useState([]);
const [total, setTotal] = useState(0);   // ❌ болгоомжтой
```

Ингэвэл `teas` өөрчлөгдөх бүрт `total`-оо гараар шинэчлэх ёстой болно. Хаа нэг газар
мартвал дэлгэц дээр буруу тоо гарна — мөн яагаад болохыг олоход хэцүү.

### Хэрхэн шийддэг вэ

Бусад state-ээс **бодож гаргаж болох** зүйлийг state болгохгүй. Ажиллах явцад нь бодно.

```jsx
const [teas, setTeas] = useState(initialTeas);
const [category, setCategory] = useState("all");

// state биш — зүгээр л бодогдож байна
const visible = category === "all"
  ? teas
  : teas.filter((t) => t.category === category);

const total = visible.reduce((sum, t) => sum + t.price, 0);
```

`teas` эсвэл `category` өөрчлөгдөхөд компонент дахин ажиллана, `visible` болон `total`
өөрөө шинээр бодогдоно. Синхрончлох зүйл байхгүй тул зөрөх боломж ч байхгүй.

**Дүрэм:** state-д зөвхөн *хэрэглэгчийн шийдсэн* зүйлийг хадгал (жагсаалт өөрөө, сонгосон
шүүлтүүр). Тэднээс гарган авч болох бүхнийг бод.

## Ойлголт 6 — Хадгалах утга ба харуулах шошго хоёр өөр

### Асуудал юу вэ

Ангиллыг датандаа шууд `"食費"` гэж хадгалвал юу болох вэ?

- Маргааш "英語にも対応したい" гэвэл бүх хуучин мөрөө засах хэрэгтэй болно
- `"食費"` гэж бичихдээ нэг тэмдэгт алдвал шүүлтүүр чимээгүйхэн ажиллахаа болино
- Кодоо уншиж байгаа хүн ямар утгууд байж болохыг мэдэхгүй

### Хэрхэн шийддэг вэ

**Датад машинд зориулсан утга, дэлгэцэд хүнд зориулсан шошго.** Хоёрын хооронд
хөрвүүлэгч нэг файл байна.

```js
// lib/categories.js
export const CATEGORIES = [
  { value: "food", label: "食費", emoji: "🍜" },
  { value: "transport", label: "交通費", emoji: "🚌" },
  { value: "other", label: "その他", emoji: "📦" },
];

export function categoryLabel(value) {
  return CATEGORIES.find((c) => c.value === value)?.label ?? value;
}
```

- Файлд, өгөгдлийн санд, API-д → үргэлж `"food"`
- Дэлгэц дээр → `categoryLabel("food")` → `"食費"`

Шошгыг өөрчлөхөд датаны нэг ч мөр хөндөгдөхгүй. Мөн ямар ангилал байж болохыг мэдэх
ганц газар үүснэ — шүүлтүүр, форм, шалгалт бүгд эндээс уншина.

### Мөнгө ч мөн адил

Датад **тоо** (`12000`), дэлгэцэд **форматлагдсан текст**:

```js
const yen = new Intl.NumberFormat("ja-JP", {
  style: "currency",
  currency: "JPY",
  maximumFractionDigits: 0,
});

export function formatYen(amount) {
  return yen.format(amount);   // 12000 -> ￥12,000
}
```

`Intl` бол хөтөчид бэлэн байдаг. Таслал тавих кодоо өөрөө бичих шаардлагагүй.

## Даалгавар 1.2 — Нэмэх, устгах

**Зорилго:** датаг state болгож, хэрэглэгч өөрчлөх боломжтой болгох.

**Тулгуурлах ойлголт:** Ойлголт 3, 4

**Алхмууд**

1. `app/page.js`-ийн эхэнд `"use client"` бич.
2. `sample.js`-с шууд ашиглахын оронд `useState(sampleExpenses)` болго.
3. `components/ExpenseForm.js` — дүн, ангилал, тэмдэглэл гурван талбартай форм. Илгээхэд
   эцэг компонент руу шинэ зардал дамжуулна.
4. `ExpenseItem` дээр устгах товч. Дарахад тухайн зардал жагсаалтаас хасагдана.
5. Жагсаалтын доор нийт дүн харагдана.

**Шинэ зардлын `id`** — `crypto.randomUUID()` ашигла. Хөтөчид бэлэн байдаг, сан
суулгах шаардлагагүй.
