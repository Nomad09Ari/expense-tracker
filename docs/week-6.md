# Долоо хоног 6 — Гар утасны аппаа дуусгах

## Өнгөрсөн долоо хоногийн асуулт

Токеныг кодод гараар бичсэн байсан. Энэ нь гурван зүйлийг илтгэнэ:

- Аппыг зөвхөн **чи** ашиглаж чадна. Өөр хүн суулгавал чиний датаг харна
- Токен хүчингүй болвол апп юу болохоо мэдэхгүй
- Нэвтрэх, гарах гэсэн ойлголт огт байхгүй

Энэ долоо хоногт тэр гурвыг шийдээд, аппаа жинхэнэ дуусгана.

> Аппын бүх текст Япон: ログイン / ログアウト / 追加 / 削除 / 保存中…

> Prompt бичих зарчим: [Claude-тай хамт код бичих](claude-ashiglah.md)

## Ойлголт 1 — Апп "нэвтэрсэн эсэх"-ээ хэрхэн мэдэх вэ

### Асуудал юу вэ

Вэб дээр энэ амархан байсан: cookie хөтөчид үлддэг, хуудас дахин ачаалагдахад
`GET /api/auth/me` дуудаад л болоо.

Гар утасны аппад хоёр зүйл өөр:

1. Токеныг **чи өөрөө** хадгалах ёстой
2. Апп нээгдэх бүрт "энэ хүн нэвтэрсэн үү?" гэдгийг **юу ч хэлэхээс өмнө** шийдэх хэрэгтэй

### Хэрхэн шийддэг вэ

Апп эхлэхэд гурван төлөвийн аль нэгэнд байна:

| Төлөв | Юу харагдах вэ |
|---|---|
| **Шалгаж байна** | Агуулагдахуйц дэлгэц (splash, эсвэл эргэлдэх дугуй) |
| **Нэвтрээгүй** | Нэвтрэх дэлгэц |
| **Нэвтэрсэн** | Зардлын жагсаалт |

Энэ нь 3 дахь долоо хоногийн "гурван төлөв"-тэй яг ижил хэв маяг: **юу ч мэдэхгүй байх
хугацааг дэлгэц дээр илэрхийлэх ёстой.** Хадгалсан токеноо уншихад хэдхэн миллисекунд
болно, гэхдээ тэр хугацаанд "нэвтрээгүй" гэж шийдэж болохгүй — эс бөгөөс апп нээх бүрт
нэвтрэх дэлгэц нэг агшин анивчиж харагдана.

```dart
enum AuthStatus { checking, signedOut, signedIn }
```

### Түгээмэл буруу ойлголт

**"Токен хадгалагдсан байвал нэвтэрсэн гэсэн үг."**

Заавал биш. Токен хуучирсан, эсвэл сервер талаас устгагдсан байж болно. Токен байгаа
эсэх нь зөвхөн **таамаг**. Жинхэнэ хариуг зөвхөн сервер л мэднэ — тиймээс эхний хүсэлт
`401` буцаавал итгэх ёстой (Ойлголт 3).

## Ойлголт 2 — Дэлгэц хооронд шилжих

Flutter-д хуудас хоорондын шилжилтийг `Navigator` гүйцэтгэдэг. Next.js-ийн `app/`
хавтасны бүтэцтэй адил автоматаар биш — **чи өөрөө дуудна**.

```dart
// нэвтрэх дэлгэц рүү шилжиж, буцах боломжгүй болгох
Navigator.of(context).pushReplacement(
  MaterialPageRoute(builder: (_) => const LoginScreen()),
);
```

`pushReplacement` нь `router.replace("/login")`-тэй ижил санаа: нэвтрэх дэлгэц рүү
шилжсэний дараа "буцах" товчоор зардлын жагсаалт руу эргэж орох боломжгүй байх ёстой.

Энэ төсөлд илүү энгийн арга бас бий: аппын дээд түвшинд нэг `StatefulWidget` байрлуулж,
`AuthStatus`-аас хамааруулан аль дэлгэцийг харуулахаа шийдэх. Навигацийн стек огт
хэрэггүй болно.

```dart
Widget build(BuildContext context) {
  switch (_status) {
    case AuthStatus.checking:
      return const SplashScreen();
    case AuthStatus.signedOut:
      return LoginScreen(onSignedIn: _handleSignedIn);
    case AuthStatus.signedIn:
      return ExpenseListScreen(onSignOut: _handleSignOut);
  }
}
```

Хоёр арга хоёулаа зөв. Аль нэгийг сонгоод, яагаад сонгосноо PR-ийн тайлбарт бич.

## Ойлголт 3 — `401` ирвэл юу хийх вэ

### Асуудал юу вэ

Хэрэглэгч аппаа долоо хоног нээгээгүй байлаа. Токен нь хугацаа дуусчээ. Тэр аппаа
нээхэд юу болох вэ?

Хамгийн муу хувилбар: 「エラーが発生しました」 гэсэн улаан бичиг гарч, хэрэглэгч юу
хийхээ мэдэхгүй гацна.

### Хэрхэн шийддэг вэ

`401` бол онцгой status code. Энэ нь "алдаа гарлаа" биш, **"чи дахин нэвтрэх хэрэгтэй"**
гэсэн үг. Тиймээс бусад алдаанаас тусад нь зохицуулна:

| Status | Апп юу хийх вэ |
|---|---|
| `401` | Хадгалсан токеноо устгаад нэвтрэх дэлгэц рүү шилжих |
| `403` | 「権限がありません」 — нэвтэрсэн, гэхдээ энэ зүйл түүнийх биш |
| Бусад | Алдааны мессеж + 再試行 товч |

Үүнийг `ApiClient` дотор нэг газар хийх нь зөв. Дэлгэц бүрт `if (statusCode == 401)`
гэж давтвал нэг өдөр нэгийг нь мартана.

Энэ бол `lib/api.js`-ийн `request()` функцтэй яг ижил санаа: **гадаад ертөнцтэй харьцах
дүрмийг нэг хаалганд төвлөрүүл.**

## Даалгавар 6.1 — Нэвтрэх дэлгэц ба токен хадгалах

**Зорилго:** апп өөрөө нэвтэрч, токеноо аюулгүй хадгалдаг болох.

**Тулгуурлах ойлголт:** Ойлголт 1, 2

**Алхмууд**

1. `flutter_secure_storage` package нэмэх
2. `mobile/lib/auth/token_store.dart` — `read()`, `save(token)`, `clear()`
3. `mobile/lib/screens/login_screen.dart` — и-мэйл, нууц үг, ログイン товч
4. `POST /api/auth/token` дуудаж токеноо хадгална
5. Аппын дээд түвшинд `AuthStatus`-аар аль дэлгэцийг харуулахаа шийднэ
6. Зардлын дэлгэц дээр ログアウト товч — токеноо устгаад нэвтрэх дэлгэц рүү

**Нэвтрэх формд заавал байх зүйлс** (4 дэх долоо хоногийнхтэй ижил зарчим):

- Талбар бүрийн доор өөрийнх нь алдаа
- Хүсэлт явж байх үед товч түгжигдэж 「ログイン中…」
- Нэвтрэлт амжилтгүй бол серверийн мессеж (и-мэйл, нууц үгийн алийг нь буруу болохыг **хэлэхгүй**)
- Нууц үгийн талбар `obscureText: true`

**Claude-д өгөх prompt-ын жишээ**

```
Flutter、Dart。UI テキストはすべて日本語。

1. flutter_secure_storage を追加し、mobile/lib/auth/token_store.dart を作る:
   read() / save(String token) / clear()

2. mobile/lib/screens/login_screen.dart:
   メールアドレスとパスワードの TextField、「ログイン」ボタン。
   POST /api/auth/token を呼び、成功したらトークンを保存して onSignedIn を呼ぶ。
   - 送信中はボタンを無効化して「ログイン中…」
   - 失敗時はサーバーからのメッセージをそのまま表示
   - パスワードは obscureText: true

3. アプリのルートで AuthStatus(checking / signedOut / signedIn) を持ち、
   起動時に保存済みトークンを読んで画面を切り替える。
   checking の間はローディング画面を出す（ログイン画面を一瞬出さない）。

制約:
- SharedPreferences は使わない（暗号化されないため）
- 状態管理パッケージは入れない。setState で足りる
- setState の前に mounted を確認する
```

**Гарсан кодыг шалгах**

- [ ] `flutter_secure_storage` ашигласан, `SharedPreferences` **биш**
- [ ] Апп эхлэхэд `checking` төлөв байна — нэвтрэх дэлгэц анивчихгүй
- [ ] Нэвтрэлт амжилтгүй үед серверийн мессеж харагдана, ерөнхий үг биш
- [ ] Токен хаана ч `print()` хийгдээгүй
- [ ] ログアウト нь токеныг **устгаж** байна, зөвхөн дэлгэц соливоогүй
- [ ] `obscureText: true` байна

**Дууссан гэж үзэх шалгуур**

- [ ] Аппаа нээхэд нэвтрэх дэлгэц гарна
- [ ] Буруу нууц үгээр нэвтрэхэд Япон мессеж гарна, апп унахгүй
- [ ] Зөв нууц үгээр нэвтрэхэд зардлын жагсаалт гарна
- [ ] **Аппаа бүрэн хаагаад дахин нээхэд нэвтэрсэн хэвээрээ** байна
- [ ] ログアウト дарж, аппаа дахин нээхэд нэвтрэх дэлгэц гарна
- [ ] Хоёр өөр хэрэглэгчээр нэвтэрч үзэхэд тус тусын зардал харагдана

## Даалгавар 6.2 — Зардал нэмэх, устгах

**Зорилго:** гар утаснаас дата өөрчлөх.

**Алхмууд**

1. `ApiClient`-д `createExpense()`, `deleteExpense(id)` нэмэх
2. Нэмэх дэлгэц эсвэл `showModalBottomSheet` — дүн, ангилал, тэмдэглэл, огноо
3. Амжилттай болмогц жагсаалтаа дахин татах
4. Устгах: жагсаалтын мөрийг чирэх (`Dismissible`) эсвэл 削除 товч
5. Амжилттай/амжилтгүйг `SnackBar`-аар мэдэгдэх
6. `401` ирвэл автоматаар гаргах (Ойлголт 3)

**Claude-д өгөх prompt-ын жишээ**

```
Flutter、Dart。UI テキストはすべて日本語。

1. ApiClient に createExpense と deleteExpense を追加。
   POST と DELETE に Authorization: Bearer を付ける。
   401 が返ったら AuthException を投げる（他のエラーとは区別する）。

2. 支出を追加する画面（または showModalBottomSheet）:
   金額・カテゴリ・メモ・日付。カテゴリは既存のカテゴリ定義から生成する。
   金額が空、0以下、数値でない場合は送信前に画面側でエラーを出す。

3. 一覧で削除できるようにする。削除後は一覧を取得し直す。

4. 成功したら SnackBar で「支出を追加しました」「支出を削除しました」。
   失敗したら赤い SnackBar にサーバーのメッセージ。

5. AuthException を受け取ったらトークンを消してログイン画面に戻す。
   この処理は ApiClient を呼ぶ側の1か所にまとめる。

制約:
- 金額は int に変換してから送る（文字列のまま送らない）
- 送信中はボタンを無効化する
- 状態管理パッケージは入れない
```

> 「金額は int に変換してから送る」гэсэн мөрийг анзаараарай. Хэрэв сервер рүү мөр
> хэлбэрээр илгээвэл өгөгдлийн санд мөр болж хадгалагдаж, дараа нь `Expense.fromJson`
> дээр `type 'String' is not a subtype of type 'int'` гэж унана. Алдаа нь Flutter дээр
> гарах ч гарал үүсэл нь энд.

**Гарсан кодыг шалгах**

- [ ] Дүнг `int` болгож хөрвүүлж байна
- [ ] `401`-ийг бусад алдаанаас ялгаж байна
- [ ] `401`-ийн зохицуулалт **нэг газар** байна, дэлгэц бүрт давтагдаагүй
- [ ] Үйлдлийн дараа жагсаалт дахин татагдаж байна
- [ ] Хүсэлт явж байх үед товч түгжигдэж байна
- [ ] Амжилт болон алдаа хоёулаа хэрэглэгчид мэдэгдэж байна

**Дууссан гэж үзэх шалгуур**

- [ ] Гар утаснаас зардал нэмэхэд **вэб дээр** refresh хийхэд гарч ирнэ
- [ ] Вэб дээр устгасан зардал гар утсан дээр шинэчлэхэд алга болно
- [ ] Хоосон дүнгээр илгээхэд алдаа гарна, сервер рүү хүсэлт **явахгүй**
- [ ] Токеноо гараар эвдээд (`token_store`-д хогийн утга хадгалаад) аппаа нээхэд
      нэвтрэх дэлгэц рүү шидэгдэнэ
- [ ] Япон текст хаана ч эвдрээгүй

### 🔍 Гурван client, нэг үнэн

### Өөрийгөө шалга

Эдгээрт хариулж чадвал төсөл дуусав:

1. Гар утасны аппаас 「追加」 дарснаас хойш вэб дээр тэр зардал харагдах хүртэл юу

3. Backend дээр гар утсанд зориулж юуг өөрчилсөн бэ? Яагаад тэр өөрчлөлт вэб талыг эвдээгүй вэ?
4. Одоо дөрөв дэх client нэмье гэвэл (жишээ нь ширээний апп) backend дээр юу хийх шаардлагатай вэ?
5. `401` ба `403` хоёрын ялгаа юу вэ? Гар утасны апп тус бүрд нь өөр өөр хариу үйлдэл
   үзүүлдэг — яагаад?
6. Токеныг `flutter_secure_storage`-д хадгалсан. Хэрэв `SharedPreferences`-д
   хадгалсан бол ямар эрсдэл гарах байсан бэ?

## Дараа нь юу хийж болох вэ

Систем бэлэн боллоо. Хүсвэл цаашид:

- **Диаграм** — ангиллаар нь зарцуулалтаа график болгох (вэб дээр Recharts,
  гар утсан дээр `fl_chart`)
- **Офлайн горим** — сүлжээгүй үед сүүлийн датаг харуулах. Энэ нь гар утасны
  хөгжүүлэлтийн хамгийн сонирхолтой сэдвүүдийн нэг
- **Push мэдэгдэл** — сар бүрийн эцэст зарлагын дүнг сануулах
- **TypeScript** — одоо суурь ойлголт бүрдсэн тул шилжихэд амархан
- **App Store / Google Play** — жинхэнэ нийтлэх процесс

Гэхдээ эхлээд амарч, хийсэн зүйлдээ баярлаарай. Хоосон хавтаснаас эхлээд, интернэт дээр
ажиллаж байгаа, хэрэглэгчтэй, өгөгдлийн сантай, **хоёр өөр төхөөрөмж дээрээс хандагддаг**
систем болголоо. Энэ бол жинхэнэ ажил.
