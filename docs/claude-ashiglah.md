# Claude-тай хамт код бичих

Кодоо Claude-аар бичүүлэх нь огт асуудалгүй. Мэргэжлийн хөгжүүлэгчид өдөр бүр ингэж
ажиллаж байна.

Гэхдээ нэг ялгаа бий. Туршлагатай хүн гарч ирсэн кодыг харангуутаа *"энэ зөв байна"*
эсвэл *"энэ хэсэг нь эргэлзээтэй"* гэдгийг мэддэг. Тэр чадвар нь код бичих чадвараас
илүү үнэ цэнэтэй, учир нь **чи бичээгүй ч чиний нэрээр repo дотор орох гэж байгаа код**
юм.

Энэ төслийн турш яг тэр чадварыг дасгалжуулна. Даалгавар бүрт **"Гарсан кодыг шалгах"**
гэсэн жагсаалт байгаа нь үүний төлөө.

---

## 1. Асуухаасаа өмнө

Асуудлаа **өөрийн үгээр 1-2 өгүүлбэрээр бич.** Толгойдоо биш — бодитоор бич.

Жишээ нь:

> "Жагсаалт дэлгэц дээр гарч байгаа. Устгах товч дархад жагсаалтаас алга болох ёстой
> байтал юу ч болохгүй байна."

Хэрэв ингэж бичиж чадахгүй байвал асуулт чинь хараахан бэлэн болоогүй байна. Тэр
тохиолдолд эхлээд ойлголтын хэсгийг дахин уншаарай.

Энэ нь Claude-д зориулсан заль биш. Асуудлаа тодорхой үг болгож чадсан үедээ хүн
өөрөө хагасыг нь шийдчихсэн байдаг.

---

## 2. Сайн prompt-д заавал байх 4 зүйл

### ① Орчин — юун дотор ажиллаж байгаа

```
Next.js App Router, JavaScript (TypeScript биш), Tailwind CSS.
```

Үүнийг бичихгүй бол Claude өөрийн дуртай сонголтоо хийнэ. Ихэвчлэн TypeScript, заримдаа
огт өөр framework буцаана. Тэгээд чи ойлгохгүй код гартаа авна.

### ② Яг юу хүсэж байгаа

Муу: `зардлын API бичээд өг`

Сайн: `app/api/expenses/route.js файлд GET болон POST хоёрыг бичээд өг. GET нь бүх
зардлыг массиваар буцаана. POST нь шинэ зардал үүсгээд буцаана.`

### ③ Хязгаарлалт — юуг битгий хий

```
Одоо байгаа lib/db.js-ийг ашигла, шинэ сан бүү суулга.
Одоогийн файлын бүтцийг бүү өөрчил.
```

Энэ мөр л хамгийн олон толгойны өвчнөөс аврана. Хязгаарлалт бичихгүй бол
"илүү сайн болгож өглөө" гэж бүхэл төслийг чинь дахин зохион байгуулсан хариу ирж болно.

### ④ Одоогийн кодоо хавсрага

Холбогдох файлаа хуулж тавь. Файл нь юу байгааг мэдэхгүй бол Claude таамаглана,
таамаг нь чиний кодтой таарахгүй.

### Бүтэн жишээ

```
Next.js App Router, JavaScript (TypeScript биш), Tailwind CSS дээр ажиллаж байна.

app/page.js дотор зардлын жагсаалт байгаа. Одоо шинэ зардал нэмэх форм нэмэх гэж байна.
Формд дүн, ангилал, тэмдэглэл гурван талбар байна. Илгээхэд жагсаалтад шинэ мөр
нэмэгдэнэ.

Хязгаарлалт:
- Шинэ сан бүү нэм, useState-ээр л шийд
- Тусдаа компонент болгож ExpenseForm.js файлд гаргана
- Tailwind ашигла, тусдаа CSS файл бүү үүсгэ

Одоогийн app/page.js:
<кодоо энд тавь>
```

## 3. Гарсан үр дүнг шалгах 5 асуулт

Кодыг төсөлдөө хуулж тавихаасаа өмнө өөрөөсөө асуу:

**① Мөр бүрийг өөрийн үгээр тайлбарлаж чадаж байна уу?**
Чадахгүй бол зогс. Асуу: *"Энэ кодыг мөр мөрөөр монголоор тайлбарлаж өг."*

**② Хичээлд яригдаагүй шинэ ойлголт орж ирсэн үү?**
`useReducer`, `useMemo`, `useCallback`, context, custom hook гэх мэт зүйл гэнэт гарч
ирвэл асуу: *"Яагаад энийг ашигласан бэ? Үүнгүйгээр яаж бичих вэ?"*
Ихэнх тохиолдолд үүнгүйгээр бичих нь энгийн, чиний одоогийн түвшинд илүү тохирсон байдаг.

**③ Ажиллаж байгааг нүдээр харсан уу?**
"Ажиллах ёстой" гэдэг нь "ажиллаж байна" гэсэн үг биш. Хөтчөө нээ, товчоо дар, үр дүнг хар.

**④ Даалгаврын шалгах жагсаалтын зүйл бүр кодод байгаа юу?**
Нэг нэгээр нь хайж ол. Байхгүй бол дутуу байна — нэмүүл.

**⑤ Хүсээгүй зүйл нэмсэн үү?**
Шинэ сан, шинэ файл, "хэрэг болно" гэсэн нэмэлт функц. Хэрэггүй бол ав.
Ойлгохгүй код төсөлд байх нь дараа нь эвдрэх газар болдог.

## 4. Хамгийн ашигтай гурван дагалдах prompt

Эдгээрийг ашиглах тусмаа хурдан суралцана:

### "Энэ кодыг мөр мөрөөр монголоор тайлбарлаж өг"
Хамгийн үнэ цэнэтэй нь. Хариултыг уншаад ойлгохгүй үг гарвал дахин асуу.
Хичээл бүрийн дараа нэг удаа хийвэл сарын эцэст ялгаа нь маш том байх болно.

### "Яагаад X биш Y-г ашигласан бэ? Хоёрын ялгаа юу вэ?"
Жишээ нь: *"Яагаад `let` биш `const` ашигласан бэ?"*,
*"Яагаад `map` биш `forEach` ашиглаагүй вэ?"*
Сонголт бүрийн ард шалтгаан байдаг. Шалтгааныг нь мэдвэл дараагийн удаа өөрөө сонгож чадна.

### "Энэ кодыг хамгийн энгийн болгож бичвэл яаж бичих вэ?"
Claude анхны хариултдаа ихэвчлэн шаардлагатайгаас илүү зүйл нэмдэг. Энэ асуултын дараа
ирэх хувилбар нь бараг үргэлж богино, ойлгомжтой байдаг.

## 5. Улаан тугууд

Эдгээр гарвал **зогсоод асуу**, битгий шууд хуул:

| Улаан туг | Юу гэж асуух |
|---|---|
| Нэг дор 200-аас олон мөр код | "Үүнийг жижиг хэсгүүдэд хувааж, нэг нэгээр нь хийе. Эхнийхээс нь эхэл." |
| `npm install ...` гэж шинэ сан суулгах | "Энэ сангүйгээр хийж болох уу? Яагаад хэрэгтэй болсон бэ?" |
| `: string`, `interface`, `type` гэсэн бичиглэл | "Энэ TypeScript байна. JavaScript-ээр бичээд өг." |
| Одоо байгаа файлын бүтцийг бүхэлд нь өөрчилсөн | "Одоогийн бүтцээ хадгалаад, хамгийн бага өөрчлөлтөөр шийдэж болох уу?" |
| Тайлбар (comment) огт байхгүй, эсвэл хэт олон | Аль нь ч муу. Гол логик дээр 1-2 тайлбар л хангалттай. |
| "Энэ бол production-д тохиромжгүй" гэж бичсэн | "Юу нь тохиромжгүй вэ? Одоо засах уу, дараа үлдээх үү?" |

## 6. Хэзээ Claude-аас асуухгүй байх вэ

Хоёр тохиолдол бий:

**Алдааны мессежийг эхлээд өөрөө уншаарай.** Терминал эсвэл хөтчийн Console дээрх улаан
текст ихэнхдээ асуудлаа шууд хэлж байдаг: `expenses is not defined`, `Cannot read
properties of undefined`. Эхний мөрийг нь уншаад 30 секунд бод. Ойлгохгүй бол тэр үед
асуу — гэхдээ алдааны текстээ бүтнээр нь хавсрага.

**"Юу хийх вэ" гэдгээ шийдэхийг битгий даалга.** Claude-с *"дараа нь юу хийх вэ?"* гэж
асуувал ямар нэг зүйл санал болгоно, тэр нь хичээлийн замаас гажиж магадгүй. Юу хийхийг
хичээл нь хэлж байгаа. Claude-ийн үүрэг бол **хэрхэн** хийхийг туслах.

---

## 7. Хамгийн богино дүрэм

> **Мөр бүрийг өөрийн үгээр тайлбарлаж чадахгүй бол тэр даалгавар хараахан дуусаагүй байна.**

Код ажиллаж байгаа нь дуусгавар биш. Ойлгосон үед л дуусна. Ойлгоогүй код нь дараагийн
долоо хоногт эргээд ирж, тэр үед юу болж байгааг мэдэхгүй болсон байдаг.

Тайлбарлуулах нь ганцхан prompt. Тэр нэг prompt-ыг алгасахгүй байх нь энэ сарын хамгийн
том ялгааг гаргана.
