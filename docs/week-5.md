# Долоо хоног 5 — Хоёр дахь client (Flutter)

## Өнгөрсөн дөрвөн долоо хоногийн үр дүн

Апп чинь бүрэн ажиллаж байна. Хөтөч → `fetch` → API route → өгөгдлийн сан → буцаад дэлгэц.

Одоо шинэ асуулт: **ижил датаг гар утасны аппаас харж болох уу?**

Хариу нь "болно", бас бараг юу ч өөрчлөхгүйгээр. Яагаад гэдгийг энэ долоо хоногт харна.

> **Энэ бол нэмэлт хоёр долоо хоног.** Долоо хоног 1–4 бол үндсэн зам. 5–6 нь түүн дээр
> нэмэгдэж байгаа зүйл.
>
> **Урьдчилсан нөхцөл: даалгавар 4.3 (Postgres) дууссан байх ёстой.** Гар утасны апп
> интернэт дэх API руу хандана. JSON файлын хувилбар Vercel дээр бичиж чаддаггүй тул
> тэр хүртэл гар утасны апп ажиллахгүй.
>
> Энэ хичээл доторх Dart жишээнүүдийг **Flutter 3.38.4 / Dart 3.10** дээр шалгасан.
> Чиний суулгасан хувилбар арай шинэ байвал асуудалгүй.

## Энэ долоо хоногт бид юуг барих вэ

Flutter дээр гар утасны апп. Энэ долоо хоногт зөвхөн **унших** — зардлын жагсаалт,
ангиллын шүүлтүүр, нийт дүн. Нэмэх, устгах нь 6 дахь долоо хоногт.

Хамгийн чухал нь: энэ бол шинэ апп биш. **Хоёр дахь client.** Дата нь ижил, сервер нь
ижил, зөвхөн харагдац нь өөр.

> Аппын бүх текст Япон хэвээрээ: 支出管理 / 食費 / 交通費 / その他 / 円.

## Ойлголт 1 — Яагаад энэ боломжтой байна вэ

2 дахь долоо хоногт нэг шийдвэр гаргасан: backend-ээ `app/api/` дотор тусад нь бичиж,
frontend-ээсээ `fetch`-ээр дуудсан. Тэр үед энэ нь илүү ажил мэт санагдсан.

**Энэ долоо хоног бол тэр шийдвэрийн шагнал.**

```
        ┌─────────────────┐        ┌──────────────────┐
        │  Хөтөч          │        │  Гар утас        │
        │  React / JS     │        │  Flutter / Dart  │
        └────────┬────────┘        └────────┬─────────┘
                 │                          │
                 │        HTTP + JSON       │
                 └────────────┬─────────────┘
                              ↓
                   ┌──────────────────────┐
                   │  app/api/expenses    │
                   │  app/api/auth/*      │
                   │  lib/db.js           │
                   │  Postgres            │
                   └──────────────────────┘
```

Хоёр client огт өөр хэл дээр бичигдсэн. Гэтэл хоёулаа ижил хаяг руу ижил JSON илгээж,
ижил хариу авч байна. Учир нь **HTTP бол хэлнээс хамаардаггүй гэрээ.**

Хэрэв 2 дахь долоо хоногт `lib/db.js`-ийг компонентоосоо шууд дуудсан бол одоо энэ
боломжгүй байх байсан. Dart дээр бичигдсэн апп JavaScript функц дуудаж чадахгүй.
Харин HTTP хаяг руу хандаж чадна.

### Backend-д ганцхан өөрчлөлт хэрэгтэй болно

Бүрэн "юу ч өөрчлөхгүй" гэвэл худал болно. Нэг зүйл таарахгүй байгаа — тэр нь
**нэвтрэлт**. Ойлголт 5-д үзнэ. Тэр өөрөө энэ долоо хоногийн хамгийн сонирхолтой хичээл.

## Ойлголт 2 — Dart нь JavaScript-ээс юугаараа ялгаатай вэ

Dart бол Flutter-ийн хэл. JavaScript мэддэг хүнд танил санагдана, гэхдээ хатуу дүрэмтэй.

| | JavaScript | Dart |
|---|---|---|
| Төрөл | заахгүй ч болно | **заана**: `String name`, `int price` |
| Хувьсагч | `const` / `let` | `final` (нэг удаа), `var` (төрлийг таана) |
| Хоосон утга | `null`, `undefined` | зөвхөн `null`, бас **зөвшөөрөл хэрэгтэй**: `String?` |
| Мөр доторх утга | `` `${name}` `` | `'$name'` |
| Жагсаалт хувиргах | `.map(fn)` | `.map(fn).toList()` |
| Шүүх | `.filter(fn)` | `.where(fn)` |
| Нийлбэр | `.reduce(fn)` | `.fold(0, fn)` |
| Эхлэх цэг | файл шууд ажиллана | `void main()` функц |
| Цэг таслал | заримдаа | **үргэлж** |

### Жижиг жишээ

Цайны цэс, Dart дээр:

```dart
class Tea {
  final String name;
  final int price;

  const Tea({required this.name, required this.price});
}

void main() {
  final teas = <Tea>[
    const Tea(name: 'ミルクティー', price: 480),
    const Tea(name: '緑茶', price: 320),
    const Tea(name: 'ブラックコーヒー', price: 380),
  ];

  final cheap = teas.where((t) => t.price < 400).toList();
  final total = teas.fold<int>(0, (sum, t) => sum + t.price);

  print('400円未満: ${cheap.length}件 / 合計 $total円');
}
```

Анзаарах зүйлс:

- `class Tea` — JavaScript-д объект зүгээр л `{ name: ..., price: ... }` байсан. Dart-д
  бүтцийг нь урьдчилж зарлах нь элбэг.
- `required this.name` — энэ талбарыг заавал өгөх ёстой гэсэн үг. Мартвал **кодыг
  ажиллуулахаас өмнө** алдаа заана.
- `<Tea>[...]` — "энэ бол `Tea`-гийн жагсаалт". Өөр зүйл хийж оруулах гэвэл зөвшөөрөхгүй.
- `.where(...)` буцаахдаа шууд жагсаалт биш, тул `.toList()` нэмнэ.

### Түгээмэл буруу ойлголт

**"Төрөл заах нь зүгээр нэг нэмэлт бичиг."**

Эсрэгээрээ — энэ нь алдааг **ажиллуулахаас өмнө** барьдаг. JavaScript дээр
`tea.prise` гэж буруу бичвэл `undefined` болоод чимээгүй цааш явдаг. Dart дээр
засварлагч чинь шууд улаанаар зурна.

## Ойлголт 3 — Widget бол компонент

Энэ хэсэг хамгийн танил санагдана. Flutter-ийн загвар React-тай бараг ижил.

| React | Flutter |
|---|---|
| Компонент | **Widget** |
| `return ( <div>… </div> )` | `Widget build(BuildContext context) { return …; }` |
| props | constructor-ийн параметрүүд (`final`) |
| props-оос өөр юу ч хэрэггүй компонент | `StatelessWidget` |
| `useState` | `StatefulWidget` + `setState` |
| `className="p-4"` | `Padding(padding: …)` гэсэн **widget** |
| `{list.map(x => <Item/>)}` | `list.map((x) => Item()).toList()` |
| `key` | `key` (ижил зорилготой) |

### Жижиг жишээ

Props-той widget:

```dart
class TeaTile extends StatelessWidget {
  const TeaTile({super.key, required this.name, required this.price});

  final String name;
  final int price;

  @override
  Widget build(BuildContext context) {
    return ListTile(
      title: Text(name),
      trailing: Text('$price円'),
    );
  }
}
```

State-тэй widget:

```dart
class Counter extends StatefulWidget {
  const Counter({super.key});

  @override
  State<Counter> createState() => _CounterState();
}

class _CounterState extends State<Counter> {
  int _count = 0;

  @override
  Widget build(BuildContext context) {
    return TextButton(
      onPressed: () => setState(() => _count++),
      child: Text('押した回数: $_count'),
    );
  }
}
```

`setState(() => _count++)` нь `setCount(count + 1)`-тэй яг ижил утгатай: **"утга
өөрчлөгдлөө, дэлгэцээ дахин зур"** гэж хэлж байна.

### Түгээмэл буруу ойлголт

**"Widget гэдэг нь товч, текст гэх мэт харагдах зүйл."**

Flutter-д **бүх зүйл widget**. Зай авах (`Padding`), голлуулах (`Center`), багана
(`Column`) — бүгд widget. HTML дээр `div` + CSS-ээр хийдэг зүйлийг Flutter-д widget-ээр
ороож хийдэг. Эхэндээ гүн ноорхой харагдана — энэ хэвийн.

## Ойлголт 4 — JSON-г объект болгох

### Асуудал юу вэ

JavaScript дээр энэ ажил байхгүй байсан:

```js
const data = await res.json();   // болоо. data.amount шууд ажиллана
```

Dart дээр `jsonDecode` нь `Map<String, dynamic>` буцаана. `dynamic` гэдэг нь
"юу ч байж болно" гэсэн үг — өөрөөр хэлбэл Dart-ийн бүх хамгаалалт унтарсан гэсэн үг.

### Хэрхэн шийддэг вэ

**Model class** бичнэ. Тэр нь "API-гаас ирэх дата ийм хэлбэртэй" гэсэн ганц эх сурвалж
болно.

```dart
class Book {
  final String id;
  final String title;
  final int pages;

  const Book({required this.id, required this.title, required this.pages});

  factory Book.fromJson(Map<String, dynamic> json) {
    return Book(
      id: json['id'] as String,
      title: json['title'] as String,
      pages: json['pages'] as int,
    );
  }
}
```

Хожим сервер талбарынхаа нэрийг `pages`-ээс `pageCount` болговол — **ганц л газар**
засна. Апп дотор `book.pages` гэж бичсэн 20 газар хөндөгдөхгүй.

Энэ бол `lib/api.js`-тэй яг ижил санаа: гадаад ертөнцтэй ярих кодыг нэг хаалганд цуглуулж,
бусад код нь цэвэр объекттой ажиллана.

### Урхи

```
type 'String' is not a subtype of type 'int'
```

Ийм алдаа гарвал API чинь тоо гэж бодож байсан талбарыг **мөр** болгож буцаасан гэсэн үг.
Жишээ нь `"amount": "3000"`. Dart үүнийг чимээгүй өнгөрөөхгүй — тэр даруй зогсооно.

Тиймээс энэ мөч нь серверийн талын датаны цэвэр байдлыг шалгах сайн боломж.
Хэрэв ийм алдаа гарвал засах газар нь Flutter биш, **backend**.

## Ойлголт 5 — Cookie гар утсанд ажиллахгүй

Энэ бол долоо хоногийн гол хичээл.

### Асуудал юу вэ

4 дэх долоо хоногт нэвтрэлтийг **cookie**-гээр хийсэн. Дурсан санавал:

- Сервер `Set-Cookie: session=…; HttpOnly` гэж буцаадаг
- **Хөтөч** түүнийг хадгалж, хүсэлт бүрт автоматаар хавсаргадаг

Гол үг нь **хөтөч**. Cookie бол хөтчийн механизм. Flutter аппад хөтөч байхгүй.

Мөн `httpOnly` нь "хуудсан дээрх JavaScript үүнийг уншиж болохгүй" гэсэн утгатай байсан.
Гар утасны аппад хуудас ч байхгүй, JavaScript ч байхгүй — тэр хамгаалалт утгаа алдана.

### Хэрхэн шийддэг вэ

Гар утасны аппууд токеноо **өөрсдөө хадгалж, гараараа хавсаргадаг**:

```
Authorization: Bearer 9f2a...c1
```

Ижил токен, ижил session хүснэгт — зөвхөн **дамжуулах суваг** нь өөр.

```
Хөтөч    →  Cookie: session=9f2a…           ┐
                                            ├→  getCurrentUser()  →  хэрэглэгч
Гар утас →  Authorization: Bearer 9f2a…     ┘
```

Backend дээр хоёр жижиг өөрчлөлт хэрэгтэй:

**① `getCurrentUser()` хоёр газраас токен хайдаг болно**

```js
import { cookies, headers } from "next/headers";

async function readToken() {
  const h = await headers();
  const auth = h.get("authorization");
  if (auth?.startsWith("Bearer ")) {
    return auth.slice("Bearer ".length);
  }

  const store = await cookies();
  return store.get(COOKIE)?.value ?? null;
}
```

**② Cookie тавихын оронд токеныг буцаадаг шинэ хаяг**

`POST /api/auth/token` — и-мэйл, нууц үг авна, `{ token, user }` буцаана.
`/api/auth/login`-тэй ижил шалгалт, зөвхөн төгсгөл нь өөр.

Энд нэг дизайны шийдвэр гарна: `createSession()` дотор одоо **хоёр ажил** хийгдэж байна —
токен үүсгэж хадгалах, мөн cookie тавих. Тэр хоёрыг салгах шаардлагатай болно. Яаж
салгахаа өөрөө шийд.

### Токеныг хаана хадгалах вэ

Гар утсан дээр `flutter_secure_storage` ашиглана. Энэ нь iOS дээр Keychain,
Android дээр Keystore руу хадгалдаг — хоёулаа үйлдлийн системийн шифрлэсэн агуулах.

`SharedPreferences` бол **шифрлэгдээгүй**. Тохиргоо хадгалахад тохиромжтой, токен
хадгалахад тохиромжгүй.

## Даалгавар 5.2 — Backend-д токен нэмэх, Flutter-ээс дата татах

**Зорилго:** гар утасны апп серверээс жагсаалт авч чаддаг болох.

**Тулгуурлах ойлголт:** Ойлголт 4, 5

**Алхмууд**

1. Backend: `lib/session.js`-ийн `getCurrentUser()` нь `Authorization: Bearer` эсвэл
   cookie-гийн аль нэгээс токен уншдаг болго
2. Backend: `app/api/auth/token/route.js` — `{ email, password }` авч `{ token, user }` буцаана
3. `docs/requests.http`-ээр шалга (доор блок нэмнэ)
4. Flutter: `pubspec.yaml`-д `http` package нэмэх
5. `mobile/lib/models/expense.dart` — `Expense` model + `fromJson`
6. `mobile/lib/api/client.dart` — `ApiClient`, токеноо түр зуур гараар өгнө
7. Токенгүйгээр нэг удаа дуудаж үз (доорх 🔍 хэсэг)

**Эмулятороос серверт хандах хаяг** — энэ бол хамгийн олон хүн бүдэрдэг газар:

| Хаанаас | Хаяг |
|---|---|
| Android эмулятор | `http://10.0.2.2:3000` |
| iOS симулятор | `http://localhost:3000` |
| Бодит төхөөрөмж (ижил Wi-Fi) | `http://<компьютерийн LAN IP>:3000` |
| Production | `https://<чиний апп>.vercel.app` |

Android эмулятор дотор `localhost` гэдэг нь **эмулятор өөрөө** гэсэн үг, чиний компьютер
биш. `10.0.2.2` нь "намайг ажиллуулж байгаа компьютер" гэсэн тусгай хаяг.

**Claude-д өгөх prompt-ын жишээ**

```dart
class _BookListScreenState extends State<BookListScreen> {
  bool _loading = true;
  String? _error;
  List<Book> _books = const [];

  @override
  void initState() {
    super.initState();
    _load();
  }

  Future<void> _load() async {
    setState(() {
      _loading = true;
      _error = null;
    });
    try {
      final books = await api.getBooks();
      if (!mounted) return;
      setState(() => _books = books);
    } catch (e) {
      if (!mounted) return;
      setState(() => _error = e.toString());
    } finally {
      if (mounted) setState(() => _loading = false);
    }
  }
}
```

`if (!mounted) return;` гэсэн мөрийг анзаараарай. Хэрэглэгч хариу ирэхээс өмнө дэлгэцийг
хааж магадгүй — тэр үед `setState` дуудвал алдаа гарна. Энэ нь 3 дахь долоо хоногт
