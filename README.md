# Зардлын бүртгэл — 4 долоо хоногийн төсөл

Энэ бол **бүтэн ажилладаг вэб апп** барих төсөл. Дуусахад чинь интернэт дээр байрлах,
хэрэглэгч бүртгүүлж нэвтэрдэг, өөрийн датагаа хадгалдаг апп үлдэнэ.

Гол зорилго нь React дээр дахиад нэг хуудас нэмэх биш. Гол зорилго нь:

> **Хөтөч дээрх товч дарахаас эхлээд, дата өгөгдлийн санд бичигдэж, дэлгэц шинэчлэгдэх
> хүртэлх бүтэн зам** толгойд чинь тодрох.

Ихэнх хүн энэ замын нэг үзүүрийг л мэддэг. Энэ төслийн дараа чи хоёуланг нь, мөн хооронд
нь холбогч бүх зүйлийг мэддэг болно.

---

## Юу барих вэ

Зардлын бүртгэл. Энгийн боловч жинхэнэ аппад байдаг бүх зүйлийг агуулна:

- Зардал нэмэх (дүн, ангилал, тэмдэглэл, огноо)
- Жагсаалтаар харах, устгах, засах
- Ангиллаар шүүх, нийт дүн бодох
- Бүртгүүлэх / нэвтрэх
- **Хэрэглэгч бүр зөвхөн өөрийнхөө зардлыг харна**

## Технологи

**Next.js** (App Router) + **JavaScript** + **Tailwind CSS**.

Next.js бол React дээр суурилсан framework. Чиний мэддэг `useState`, `useEffect`,
компонент, JSX бүгд яг адилхан ажиллана. Next.js нэмээд өгч байгаа зүйл нь:

- Хуудас хоорондын шилжилт (routing) — файлын бүтцээр л зохицуулагдана
- **Backend** — ижил төсөл дотор `app/api/` хавтас руу сервер тал бичнэ
- Интернэт рүү гаргах (deploy) нь маш хялбар

Нэг л хэл (JavaScript), нэг л төсөл, нэг л `npm run dev`.

## Яагаад backend-ээ тусад нь бичих вэ

Next.js-д богино зам бий. Компонент дотроосоо **шууд** өгөгдлийн сан руу хандаж болдог
(үүнийг server component гэдэг). Мөр цөөрнө, хурдан бичигдэнэ.

Энэ төсөлд бид тэр богино замыг **зориуд ашиглахгүй.** Оронд нь backend-ээ `app/api/`
дотор тусад нь бичээд, frontend-ээсээ `fetch`-ээр дуудна. Гурван шалтгаантай.

**① Юу болж байгааг нүдээр харна.**
Богино замаар явбал дата ямар нэг байдлаар компонент дотор гарч ирнэ — хаанаас, яаж
ирснийг харахгүй. `fetch`-ээр дуудвал хүсэлт бүр хөтчийн Network таб дээр жагсаж
харагдана: ямар method, ямар URL, ямар status code, хэдэн миллисекунд болсон.
Гараар нээж хардаг зүйл бол ойлгоход хамгийн хялбар зүйл.

**② Дата ганц, түүнийг хэрэглэгч нь олон.**
`app/api/expenses` бол жинхэнэ HTTP хаяг. Гар утасны апп, өөр вэбсайт, энгийн скрипт —
хэн ч хандаж чадна. Харин React компонентыг гар утасны апп дуудаж чадахгүй. Backend-ээ
тусад нь барьсан цагт хоёр дахь, гурав дахь client нэмэхэд backend-ээ огт хөндөхгүй.

**③ Ихэнх систем ингэж баригдсан байдаг.**
Backend нэг талдаа, client нөгөө талдаа, хооронд нь HTTP. Энэ бүтцийг нэг удаа өөрөө
барьсан хүн дараа нь ямар ч төсөл дээр өөрийгөө олно.

Богино замыг 4 дэх долоо хоногийн төгсгөлд танилцуулна. Урт замаар нэг удаа явж, юу
болж байгааг харсан хүн богино замыг ойлгож ашиглана. Эсрэгээр нь болдоггүй.

## Эхлэх

```bash
git clone <repo-url>
cd expense-tracker
npm install
npm run dev
```

→ http://localhost:3000

## Ажлын урсгал

1. Долоо хоногийн хичээлээ уншина (`docs/week-N.md`)
2. Шинэ branch үүсгэнэ: `git switch -c week1/ui`
3. Даалгавраа хийж, жижиг жижиг commit хийнэ
4. PR нээнэ → санал зөвлөгөө яриад → `main` руу нэгтгэнэ

`main` руу шууд push хийхгүй. Бүх зүйл PR-аар дамжина — жинхэнэ багууд ингэж ажилладаг.
